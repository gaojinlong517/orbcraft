# 构筑界面 · 视觉重设计

> 对象：游戏内构筑菜单（`BuildScreenGui`），由 `/orb build` 或按键 `O` 唤起。
> 技术约束：Minecraft 1.21.11 GUI，只能画矩形与文字，没有 CSS、圆角、阴影、自定义字体。
> 结论：**v1 的问题不是「不好看」，是没有层级**——标题、选项卡、动作三类信息在视觉上是同一层。

## 一、当前 UI 的主要问题（评审结论）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **无信息层级** | 标题与按钮同字号；面板只有一块半透明黑，没有表头/分区 | 玩家第一眼找不到「现在该干什么」 |
| 2 | **卡片没有「卡」的感觉** | 全是原版灰按钮，无选中条、无状态点、无次要信息 | 选项之间无法比较，只能逐个读字 |
| 3 | **颜色语义丢失** | 聊天版用绿/红/金表达「可确认/危险/特殊」，GUI 版所有按钮都是同一个灰 | 危险操作（放弃）和主操作（确认）长得一样 |
| 4 | **布局不随屏宽变化** | 固定 2 列、固定按钮宽度 | 窄窗口挤压文字，宽窗口大片空白 |
| 5 | **交互细节缺失** | 无 hover 反馈、无焦点环、无键盘操作、无快捷键提示 | 只能用鼠标；键盘玩家被排除 |
| 6 | **对比度不足** | 金黄标题落在 `#101010` 90% 底上，卡片边界几乎不可见 | 明亮地形上文字发飘，看不清分区 |

结论分档：**重做视觉层**（结构可留，外观与交互需重写）。

## 二、四位专家视角的评估与建议

### 2.1 布局与信息层级（信息架构视角）

**判断**：当前是「一堆按钮」，不是「一屏有主次的操作界面」。

**建议**：
1. **三段式**：表头（我在哪）→ 主体（选什么）→ 动作区（下一步做什么）。三段之间用**留白+分隔线**而不是颜色块区分，避免整屏花。
2. **选项与动作分离**：选项走网格（可比较），动作走底部单行右对齐（可预期）。玩家找「确认」永远在右下角，不需要每次扫一遍。
3. **标题即状态**：标题行直接复用服务端的状态文案（`[构筑] 类型层 · 请选择类型`），不另写一句，避免两处不一致。
4. **单屏原则**：一屏只做一件事。当前实现已经把四层拆成四屏，保持。

### 2.2 配色与视觉风格（视觉设计视角）

**判断**：缺少色板与用色纪律。强调色被滥用（所有按钮都在抢注意力）。

**建议**：
1. **深色底 + 低饱和卡片 + 单一强调金**。强调色只允许出现在两处：标题、选中态。其余一律中性灰阶。
2. **语义色只表达状态，不表达美观**：绿=可确认、红=危险/放弃、金=特殊（开发工具）、青=定向卡、灰=不可用。
3. **明度阶梯拉开**：面板 `#121216` < 卡片 `#23232C` < hover `#2F2F3A`，相邻层级至少差 10 个明度值，灰度打印也能分出三层。
4. **正文不用纯白**：`#E6E6EE`，纯白在深底上会「发光」，长时间阅读刺眼。
5. **禁忌**：不用渐变堆叠、不用彩虹色、不用纯黑描边（会显脏）。

### 2.3 组件一致性与交互细节（组件视角）

**判断**：聊天版与 GUI 版是两套观感，同一个「确认」在两个入口长得完全不一样。

**建议**：
1. **按钮只有一种组件**（`CardButton`），通过 `tone / chosen / action` 三个属性派生全部外观，不新增第二种按钮。
2. **三种状态必须可辨**：默认 / hover 或键盘焦点 / 不可用。当前 hover 只改底色，焦点不可见——加上边框提亮。
3. **选中态用「左色条 + 文字变色」双通道**，不只靠 `✓` 前缀（缩略图测试下 `✓` 看不清）。
4. **动作按钮文字居中、选项按钮文字左对齐**：居中是「点一下就走」，左对齐是「用来比较」。
5. **交互反馈**：点击后不关界面，由服务端推新快照原地刷新——避免「点了闪一下又弹回来」。
6. **不可点也要看得见**：`active=false` 时保留文字（暗灰）而不是隐藏，玩家需要知道「这里有个选项，但现在不能选」。

### 2.4 响应式与可访问性（可用性视角）

**判断**：固定两列在小窗口会截断，且完全没有键盘路径。

**建议**：
1. **列数自适应**：面板宽 ≥460 用 3 列，否则 2 列，极窄 1 列；面板宽度 `min(屏宽-40, 560)`。
2. **命中区**：卡片高 24px、间距 8px，满足「不精确点击」；动作按钮最小宽 64px。
3. **键盘全通路**：继承原版 `Button` 即获得 Tab 遍历 + Enter/空格激活 + 焦点朗读，不自己写命中检测。
4. **快捷键提示常驻**：底部固定一行「Tab 切换 · Enter 确认 · Esc 关闭」。
5. **不暂停世界**：`isPauseScreen=false`，否则单人模式下开界面会停住孵化。
6. **文字溢出（2026-10-21 修正）**：原方案是「截断加 `…`」，实测玩家看不到完整词条名 —— 这是把「版面整齐」排在了「信息完整」前面，顺序错了。改为：
   - 先测量：按最长文案反推列数（3 → 2 → 1）；
   - 单卡最多两行，卡高从 24 变 34；
   - 标题最多两行；动作按钮放不下就换行；
   - 仍放不下才截断，且 hover 给全文。
   原则：**截断是最后手段，不是默认行为。**
7. **待验证**：低分辨率（854×480）下 3 列是否会挤压——当前按 460 阈值切换，需实机确认。

## 三、整合后的统一设计方案

### 3.1 设计 token（唯一事实来源）

| 类别 | 名称 | 值 | 用途 |
|---|---|---|---|
| 面板 | `PANEL_BG` | `#121216` @ 94% | 整屏底 |
| 面板 | `PANEL_BORDER` | `#3C3C48` | 1px 外框 |
| 面板 | `HEADER_BG` | `#1B1B22` | 表头带 |
| 卡片 | `CARD_BG` | `#23232C` | 默认 |
| 卡片 | `CARD_BG_HOVER` | `#2F2F3A` | hover / 焦点 |
| 卡片 | `CARD_BG_DISABLED` | `#1A1A20` | 不可用 |
| 卡片 | `CARD_BORDER` / `_HOVER` | `#373742` / `#8A8AA0` | 描边 |
| 文字 | `TEXT` | `#E6E6EE` | 正文 |
| 文字 | `TEXT_MUTED` | `#8C8C9A` | 提示 |
| 文字 | `TEXT_DISABLED` | `#64646F` | 不可用 |
| 强调 | `ACCENT` | `#FFC24B` | 标题、下划线、特殊动作 |
| 语义 | 成功 / 危险 / 信息 | `#5BD37A` / `#FF6B6B` / `#4FD1E0` | 确认 / 放弃 / 定向 |

间距与尺寸：`8`（组件间）、`14`（面板内边距）、`24`（单行卡高）、`34`（双行卡高）、`22`（动作按钮高）。
面板宽度上限 `620`，随窗口收缩到 `屏宽-24`。

### 3.2 布局规则

```
┌────────────────────────────────────────────┐ ← 外框 1px
│ 标题（金）+ 下划线 2px                      │ ← 表头带，高 12+14
├────────────────────────────────────────────┤
│ [卡片] [卡片] [卡片]                        │ ← 网格：3 列（宽≥460）或 2 列
│ [卡片] [卡片] [卡片]                        │   卡高 24，间隙 8
│                                            │
│ ────────────────────────────────────────   │ ← 分隔线 1px
│                    [次要] [主操作] [危险]   │ ← 动作行，右对齐，高 22
│ Tab 切换 · Enter 确认 · Esc 关闭            │ ← 提示，常驻
└────────────────────────────────────────────┘
```

**分类规则（硬契约）**：`orb card N`、`orb target X` → 选项卡；其余命令 → 动作行。
不按文案判断——文案会改，命令是两端契约。

### 3.3 状态规格

| 状态 | 底色 | 描边 | 文字 | 附加 |
|---|---|---|---|---|
| 默认 | `#23232C` | `#373742` | `#E6E6EE` | 右侧状态点（色调） |
| hover / 焦点 | `#2F2F3A` | `#8A8AA0` | `#FFFFFF` | 同上 |
| 选中 | `#23232C` | `#373742` | 色调 | 左侧 3px 色条 |
| 不可用 | `#1A1A20` | `#373742` | `#64646F` | 状态点变暗 |

## 四、落地情况

**已实现**（`fabric/.../client/BuildScreenGui.java`）：
- 三段式布局、表头带、标题下划线、分隔线、常驻快捷键提示
- `CardButton` 单组件派生四种状态；选中左色条；右侧状态点
- 列数自适应（3/2/1）；文字按像素截断；动作行右对齐
- 键盘通路（Tab/Enter）与焦点朗读继承原版 `Button`
- 颜色与间距全部收敛为常量，改主题只动 token 段

**未做 / 待定**：
- **文字换行（已补 2026-10-21）**：卡牌支持两行、标题两行、动作换行；hover 显示全文。
- **卡片无法显示图标与词条数**：载荷里只有 `{label, cmd, tone}`，要加图标需服务端补 `icon` 与 `detail` 字段（约 20 行），并按 `tone` 渲染迷你图形。属下一轮。
- **hover 提示（tooltip）**：聊天版有 hover 文案，GUI 未透传，需扩展载荷加 `tip`。
- **滚动**：选项超过 9 个时面板会变高，当前未做滚动，靠列数压缩。实际最多 9 张牌 + 4 个动作，2K 分辨率下不会溢出。
- **低分辨率实测**：854×480 下 3 列切换阈值需实机确认。
