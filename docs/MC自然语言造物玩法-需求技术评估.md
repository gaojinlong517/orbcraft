## 0. 两个决策的结论

| 决策 | 结论 | 关键前提 |
|---|---|---|
| AI 建模 | ✅ **可落地，但只能是离线批量生产**，不能实时 | 必须走「数据驱动模型 + 版本化资源包」，且**玩家需重载资源包** |
| 概率失控 | ✅ **强烈支持**，这是比"随机攻击"高一个维度的设计 | 必须可感知、有上限、不致死，否则玩家会当成 bug |

> **勘误**：v0.2 我说"AI 无法建模"，这句话需要精确化 —— 不是不能，而是**生成的产物无法在游戏运行时即时生效**。容器换了（离线排产），结论就从"不可行"变成"可行，但要接受延迟"。

## 1. AI 建模的真实边界

### 1.1 三条必须接受的硬约束

**① Java 版实体模型不能靠资源包直接替换**

这是 Java 版和基岩版最大的差异。基岩版有 `models/entity/*.geo.json` + `render_controllers`，纯资源包就能定义任意模型；**Java 版的实体渲染是硬编码在客户端代码里的**，资源包只能换贴图。

所以服务端要"自定义外观的实体"，只有两条路：

| 路线 | 实现 | 玩家成本 | 我们的选择 |
|---|---|---|---|
| **纯服务端**（ItemDisplay 渲染） | 隐形原版实体做 AI 载体 + `ItemDisplay` 挂自定义模型，每 tick 同步位置朝向 | **零安装** | ✅ **推荐** |
| 客户端 Mod（GeckoLib） | 真实体 + 客户端渲染器 | 必须装 Mod | ❌ 小游戏不能要求装 Mod |

纯服务端的做法是成熟方案（ModelEngine 等商业插件就是这么干的）：**隐形僵尸/劫掠兽负责寻路、攻击、伤害、击退，ItemDisplay 负责长什么样**。原版 AI 白送，外观完全自定义。
代价：每个实体每 tick 多一次 teleport 发包 + 一次 transform 同步。40 个实体约增加 1~2ms tick 开销，可接受。

**② 资源包变更必须客户端重载**

新增一个模型 = 资源包内容变了 = 玩家必须重载才能看到。无法热更新。
所以 AI 建模的产物**不可能在玩家点击描述后的几十秒内出现**。

**③ 模型必须是长方体拼装**

MC 的模型系统只有 cube，没有三角面。任何 AI 生成的网格都要先体素化/重网格化成 <300 个 cube，否则客户端直接卡死。

### 1.2 三级生产方案（核心结论）

| 级别 | 做法 | 延迟 | 成本 | 观感差异 | 适用 |
|---|---|---|---|---|---|
| **L1 · AI 配色 + 程序化贴图** | 人工骨架 + AI 出「设计 DNA」（色板/材质标签/形变参数），程序按 UV 区域烘焙贴图 | **< 100ms** | 近乎零 | ★★★★ | 90% 的普通产物 |
| **L2 · AI 调形变参数** | 骨架预留可调 ModelPart（角长/翼展/躯干/尾巴节数），AI 输出参数，程序 scale | **< 100ms** | 低 | ★★★★☆ | 稀有/史诗产物 |
| **L3 · 文生 3D 全流程** | 文生 3D API → 体素化重网格 → 骨骼近似绑定 → UV 烘焙 → 导出模型 | **小时级** | 每模型 $0.1~0.5 + 管线自研 2~4 周 | ★★★★★（需人工过审） | **只给传说级** |

**推荐组合：L1 + L2 全覆盖，L3 只作为传说级产物的离线特供。**

这个组合有个漂亮的副作用：**L3 的小时级延迟，正好和"越难越久"的设定吻合**。传说级产物告诉玩家"需要 24 小时凝形"，玩家不但不觉得是缺陷，反而觉得是仪式感。而 L1/L2 保证 90% 的日常体验是秒出。

> 这也解决了一个隐藏矛盾：如果所有产物都秒出，那"孵化时间"纯属假的幻术；如果都是真的，日常体验就崩了。分层之后，**日常是幻术、传说级是真延迟**，两者各得其所。

### 1.3 生产管线

```
玩家描述
   │
   ▼
【实时 · 毫秒级】
  语义检索模型库（embedding） ── 命中 → 分配槽位 ID + L1/L2 参数 → 孵化球直出
   │
   └─ 未命中（约 10%）→ 入离线队列
                            │
                            ▼
【离线 · 小时级】
                     批量烘焙（L3 管线）→ 自动质检 → 人工过审 → 入模型库
                            │
                            ▼
                     重新打包资源包（版本 +1）→ 玩家下次进服生效
```

**槽位化**：预置 512 个模型槽位，每个槽位 = 一个 `ItemDisplay` 的 model key。实时路径只传 `slot_id` + 缩放 + 配色，不传模型文件。这是把"实时"和"离线"解耦的关键。

## 2. 概率性攻击 → 失控度系统

改成概率事件后，设计空间一下子打开了。建议做成一个显式的数值：**失控度 Instability（0~100）**。

### 2.1 数值设计

| 来源 | 变化 |
|---|---|
| 初始值（按稀有度） | 普通 10 / 稀有 25 / 史诗 45 / 传说 65 |
| 每次攻击命中 | +2 |
| 每损失 10% 生命 | +3 |
| 主人附近有村民/宠物 | +5（仇恨干扰） |
| 每 5 秒自然衰减 | −1 |
| 达到 100 | 强制暴走（清空后回到初值） |

**触发判定**：每 30 秒 roll 一次，`P = instability / 200`
→ 传说级恶龙（65）平均每 90 秒左右失控一次，节奏刚好让玩家紧张但不烦。

### 2.2 失控事件表

| 事件 | 权重 | 效果 |
|---|---|---|
| 误伤附近生物 | 35 | 攻击最近的无关生物 |
| 顶撞主人 | 20 | 击退 + 2 心伤害 |
| 喷吐火球 | 15 | 前方 8 格点燃（不破坏方块） |
| 原地咆哮 | 15 | 范围击退 + 音效（无伤害，纯气势） |
| 瞬移偏离 | 10 | 随机脱离 20 格 |
| 短暂暴走 | 5 | 10 秒内攻击所有非主人目标 |

### 2.3 三条不可妥协的底线

1. **单次失控伤害 ≤ 4 心**，且对主人减半 —— 玩家满血 20 心，永远不会被一击带走
2. **失控不致死**：主人血量低于 2 心时，失控伤害强制归零
3. **必须可感知**：精灵球 lore 显示「稳定性 74%」；实体头顶粒子颜色随失控度从绿→黄→红；触发前 0.5 秒有变色+音效预告

**第 3 条是成败关键。** 概率事件的乐趣来自"我能预判它的不稳定"，如果你不给反馈，玩家只会认为"这龙有 bug，老打我"。有反馈之后，玩家会开始算计"它红了，我先撤"—— 这才是玩法。

**工程要求**：随机数必须可审计（seeded + 每次 roll 落日志），否则玩家投诉时你无法自证不是 bug。

## 3. 修订后的 MVP 分期

| 期 | 内容 | 周期 | 验收 |
|---|---|---|---|
| 一期 | 孵化球（进度条 A+B）+ 装备/消耗品生成 + 战力预算 | 2 周 | 5 人并发 10 秒内出活 |
| 二期 | 骨架 3 个 + 隐形载体 + ItemDisplay 同步 + 失控度系统 | 3 周 | 40 实体下 TPS ≥ 19 |
| 三期 | 槽位扩到 512 + L1/L2 实时生成 + 资源包版本化下发 | 3 周 | 同描述不重复外观 |
| 四期 | L3 离线管线（仅传说级）+ 人工过审流程 | 4 周 | 传说级 24h 交付 |

**关键路径变化**：模型资产从"3~5 天人工"变成"框架设计 + 512 槽位 + 实时参数化生成"，工作量上去了，但换来的是**无限内容**。这是这个项目最划算的一笔投资。

## 4. 新增风险

| 风险 | 等级 | 应对 |
|---|---|---|
| L3 文生 3D 质量不可控（骨骼错乱、比例畸形） | **高** | 只用于传说级 + 100% 人工过审 + 不合格退回 L2 |

| 资源包体积膨胀（512 模型） | 中 | 单模型 <300 cube，贴图统一 64×64 atlas，总包控制在 20MB 内 |

| 槽位耗尽 / 重复外观被识破 | 中 | 512 槽位 × L1/L2 参数组合 ≈ 十万量级，实际不会撞 |

## 5. 配额与槽位系统

### 5.1 配额矩阵

| 类别 | 配额 | 判定依据 | 超限行为 |
|---|---|---|---|
| 装备类 EQUIPMENT | **2 件** | 已刻印道具数（非背包总数） | 禁止激活第 3 件 |
| 主宠 ATTACK / GUARD | **1 个** | 存活的该模式召唤物数 | 拒绝投掷，球退回背包 |
| 混乱 CHAOS | **无配额** | — | 仅受全服实体硬顶约束 |

### 5.2 三个必须堵的漏洞

**① 混乱类会变成"免费军队"**

玩家先召 1 只攻击主宠，再召 5 只混乱 → 实际是 6 打 1。**"不限制"必须靠"不可控"来平衡，不能靠数量限制。**

修法：混乱型必须真的混乱 ——
- 攻击目标从「最近的敌人」改为「最近的**任意**生物」，含主人、含其他召唤物
- 不接受任何指令（不能召回、不能指定目标、不能跟随）
- **混乱型之间互相攻击** → 自然衰减，玩家无法囤积出一支军队

这样混乱型的定位就变成：**一种高风险的环境现象**，而不是战斗力。它会自己打起来、会误伤主人，玩家召它更像是在赌运气。

**② 配额绑定在物品上 → 可以用丢弃/交易腾挪**

玩家把装备丢地上（槽位释放）→ 生成新的 → 捡回来 → 无限装备。

修法：槽位绑定「玩家 UUID + 刻印记录」，**物品离手不释放槽位**；解契需主动操作且有冷却；物品彻底丢失后由系统 5 分钟自动回收，防止槽位永久卡死。

**③ 检查时机必须三处一致**

| 时机 | 动作 |
|---|---|
| 描述提交时 | 预估并提示（"装备槽已满，产物将无法激活"） |
| 孵化完成时 | 复核（不通过则球变灰，材料不退） |
| **投掷时** | **最终裁决**（期间玩家状态可能变了） |

只查最后一处，玩家会白等几分钟然后被拒，这是最招骂的体验。

### 5.3 建议升级：把两套配额合并成「统御力」池

现在是三条独立规则。每加一个新类别（坐骑、建筑、法术）就得再加一条，后期平衡会失控。

建议统一成一个资源池，各类别按强度定价：

| 类别 | 消耗 | 上限 5 点 |
|---|---|---|
| 装备 | 1 点 / 件 | → 等价于 2 件 + 余量 |
| 守护宠物 | 2 点 | |
| 攻击宠物 | 3 点 | |
| 混乱宠物 | 1 点 + 自带风险 | 理论可召 5 只，但它们会自相残杀 |

**好处**：玩家面对的是一个连续可计算的资源，取舍有深度（"我要 2 件装备 + 1 只守护，还是 1 件装备 + 1 只攻击宠"）。而且以后加新内容只需定价，不用再加规则。你原来那三条规则可以完全用这个池复现。

### 5.4 边界情况（最容易出事的地方）

| 场景 | 处理 | 原因 |
|---|---|---|
| 玩家死亡掉落 | 刻印保留，物品丢失 5 分钟后自动解契 | 立即释放会被"丢地上给朋友"利用 |
| 玩家下线 | 召唤物保留 **5 分钟**再消散 | 立刻消散太伤；永久保留会被挂机囤宠 |
| 跨维度传送 | 召唤物跟随 | 否则过个传送门就丢宠 |
| **服务器重启** | **召唤物状态必须持久化到 DB 并恢复** | 否则每次重启全员丢宠，玩家会炸 |

最后一条是硬需求：`召唤物表（uuid, owner, spec_id, spawn_at, ttl, mode, instability）` 必须在启动时重建实体。这个表还会顺便给你带来召唤历史、战报统计等运营数据。

## 6. 单机 / 联机双模式

### 6.1 平台现实：单机跑不了插件

MC 的单机模式是"客户端内嵌服务端"（Integrated Server），逻辑和多人服务器同源，但**没有 Bukkit/Paper 那一层**。所以：

| 平台 | 单机 | 联机 | 玩家安装 |
|---|---|---|---|
| Paper 插件 | ❌ 不支持 | ✅ 官方服务器，零安装 | 无 |
| Fabric / Forge 模组 | ✅ 原生支持 | ✅ 局域网 + 自建服（玩家需装同版本 Mod） | 装 Mod |

**结论：要单机，就必须有 Mod 版本。这不是选择题，是物理事实。**

### 6.2 架构改造：抽出共享内核

```
crystal-core/            纯 Java，零平台依赖
  ├─ spec/               Spec 定义、序列化
  ├─ hatch/              孵化状态机
  ├─ quota/              配额引擎（统御力池）
  ├─ budget/             战力预算裁决
  ├─ generate/           规则引擎 + LLM 客户端
  └─ adapter/            WorldAdapter / EntityAdapter / ItemAdapter 接口

platform-fabric/         实现 adapter，供单机与自建服
platform-paper/          实现 adapter，供官方联机服
```

两个平台**真正不同的只有三处**（其余全部复用）：
1. 世界/实体/物品 API（Bukkit API vs Mojang 映射）
2. 渲染层挂载（`ItemDisplay` 两边都是原版实体，反而一致）
3. 生成后端（单机走本地，联机走云端）

这套结构在 MC 生态有成熟先例（Architectury / MultiLoader），不是自创。抽象层本身约需 2 周，之后每加一个功能只需要写一份。

### 6.3 "离线"才是真问题：没有网络，谁来生成？

这是这条需求里最容易被忽略的矛盾 —— **玩法依赖 LLM，而离线没有 LLM**。

**核心建议：把架构从「LLM 优先」翻转为「规则引擎优先，LLM 兜底」。**

规则引擎不需要任何模型：分词 + 词典 + 模板匹配。

| 维度 | 词表示例 | 映射结果 |
|---|---|---|
| 元素 | 火 / 冰 / 雷 / 毒 / 光 / 暗 / 岩 / 风 | 伤害类型 + 粒子 + 贴图配色 |
| 形态 | 剑 / 弓 / 斧 / 杖 / 护甲 / 苹果 / 龙 / 兽 / 精灵 | 载体物品或骨架槽位 |
| 效果 | 吸血 / 爆炸 / 加速 / 飞行 / 隐身 / 传送 | 数据组件与属性 |
| 程度 | 微 / 强 / 极 / 毁天灭地 | 稀有度权重 |

命中后按战力预算分配数值，毫秒级出结果。

**为什么这是主方案而不是降级方案：**
- **零成本**：日常 70~80% 的描述不再调 API，费用直接降一个数量级
- **零延迟**：孵化时间变成纯粹的玩法节奏，而不是"等技术返回"
- **天然离线**：单机不装任何模型也能完整玩
- **可解释**：玩家说"火焰之剑"得到火属性剑，符合直觉；LLM 有时会给出难以理解的组合

**三级降级链：**

```
描述输入
  → 规则引擎能解析？ ── 是 ──→ 直接生成（毫秒，零成本）
                      └ 否 → 在线？ ── 是 ──→ 云端 LLM（创意描述，如"能斩断时间的刀"）
                                       └ 否 ──→ 模板 + 随机修饰符
                                                提示"离线模式仅能识别基础要素"
```

第三级保证**永远有产出**，绝不卡住玩家 —— 这一点比"生成得多好听"重要得多。

### 6.4 三种运行形态的能力矩阵

| 能力 | 纯单机 | 局域网 / 自建服 | 官方联机服 |
|---|---|---|---|
| 描述生成 | 规则引擎（+可选本地小模型） | 规则引擎 + 可选云端 | 规则引擎 + 云端 LLM |
| 孵化球 / 配额 / 失控 | ✅ 全量 | ✅ 全量 | ✅ 全量 |
| 自定义外观 | ✅ 资源包随 Mod 内置 | ✅ 同左 | ✅ 服务端推送 |
| 多人配额互斥 | 无意义 | ✅ | ✅ |
| 数据持久化 | 本地存档 | 服务端文件 | MySQL |

## 7. 电脑 AI 角色

### 7.1 先分清四个层级（这是成本分水岭）

| 层级 | 能力 | 技术 | 单次开销 |
|---|---|---|---|
| **L1 假人** | 站着、播台词、能交易 | 村民 + 自定义交易表 / ArmorStand | 极低 |
| **L2 有行为** | 跟随、寻路、战斗、巡逻、守卫 | 行为树 + 隐形载体（复用 §1.1 那套） | 低 |
| **L3 有人格** | 有偏好、记仇、主动做事、台词有性格 | 出生时生成人格档案 + 行为树权重 + 台词库 | 中（**仅创建时 1 次 LLM**） |
| **L4 实时对话/决策** | 自由对话、实时推理 | 每次交互调 LLM | **高，不可行** |

**L4 在游戏里做不了**：每次交互延迟 1~3 秒、成本随对话量线性上涨、玩家根本不会等。业内至今没有成功的实时 LLM NPC 商业案例。不要往这个方向投入。

### 7.2 推荐 L2 + L3：人格只在出生时生成一次

```
创建 AI 角色时（1 次 LLM 调用，或规则引擎直接组合）
  → 人格档案：性格 / 偏好 / 厌恶 / 台词模板 / 决策权重 / 交易倾向
  → 存进 DB

运行时（0 次 LLM）
  → 行为树读权重 → 决定做什么
  → 台词库 + 变量填空 → 说什么
```

这样每只 NPC 终身成本只有一次调用，而玩家感受到的是"它有脾气"—— 因为它选择攻击谁、拒绝和谁交易、说哪句话，确实被那份档案驱动。

**离线时**：人格档案由规则引擎用「职业 × 性格 × 口头禅」字段组合生成，同样不需要 LLM。所以这个功能在纯单机模式下也完整可用。

### 7.3 和主玩法天然咬合：AI 角色本身也是"可造物"

这是我认为最值得做的一步 —— 把 `product_type` 再加一个值 `NPC`：

> 玩家描述「一个厌恶火焰的老铁匠」
> → 生成 NPC：职业=铁匠、性格=固执、厌恶=火焰、交易表=矿类、口头禅=「又是火，走开」

于是"造万物"自然延伸成了"造人"。而且这不需要新框架：用的就是同一套 Spec、同一套孵化球、同一套配额（AI 角色占主宠槽或独立槽位）。

**这也顺便解决了"单人玩很孤独"的问题** —— 单机玩家可以给自己造几个有性格的居民。

### 7.4 技术实现要点

- 载体：复用隐形原版实体 + ItemDisplay（与召唤物同一套代码）
- 交易：Paper 用 `Merchant` API，Fabric 用对应 Vanilla 接口
- 行为树：自写轻量实现即可，200 行以内，不要引第三方库
- 寻路：直接用原版 `PathNavigation`，不要自己算

## 11. 新暴露的四个冲突

### 11.1 「攻击所有非主人玩家」在联机服等于屠杀工具

单人/局域网没问题。但官方服务器上，玩家 A 花材料召一只攻击型恶龙，它无差别追杀全服所有玩家 —— **这不叫宠物，这叫花自己的材料给全服投放一个杀手**。

三种解法（必须选一个）：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 敌对标记制** | 只有主人手动标记为敌对的玩家才会被攻击（类似 PVP 开关） | 最安全，但少了"放狗咬人"的爽感 |
| **B. 分场景配置** | 单机/局域网默认"攻击所有非主人"；官方服默认"只打敌对目标"，服主可改 | 实现最省事，推荐 |
| **C. 承认它是 PVP 玩法** | 全开放，但配套免战区、主城保护、击杀者的召唤物红名 | 最刺激，但生态最脆 |

### 11.2 建筑不能用造物的技术栈

**关键认知：AI 不可能逐方块生成建筑。** 一座 20×20×10 的城堡是 4000 个方块，任何模型都输出不了这个体量的坐标表。

正确做法是**模块化拼装**（见上图）：预置模块库（地基/墙体/塔楼/城门/屋顶/护城河/道路/桥），生成侧只决定「选哪些模块 + 怎么拼 + 什么材质 + 多大尺寸」，程序负责摆放。

这带来四个必须定义的新问题：

- **选址**：玩家脚下？指定坐标？需要「预览 → 确认」机制吗？（强烈建议要，否则城堡会压掉别人的家）
- **碰撞与地形保护**：不能覆盖玩家已有建筑、不能填埋矿洞、不能堵住村庄门口
- **面积预算**：建筑不该受召唤配额管，需要独立的「建筑面积」上限（建议单座 ≤ 2000 方块，每人 ≤ 3 座）
- **"交通"具体指什么**：道路？桥梁？矿车轨道？传送门？这个词太宽，必须先缩窄

### 11.3 沙盒模式与材料经济互斥

沙盒模式通常是创造模式、无限资源。但造物需要材料 —— 如果沙盒无限材料，那稀有度、材料经济、袭城掉落的整条链全部失效，玩家可以无限刷传说级。

建议：**沙盒模式下材料无限，但每日 5 次限制照常生效**。用次数而不是材料来制造稀缺性，规则不变、平衡不崩。

### 11.4 混乱体野怪化之后，配额管不住它

"混乱体算野怪"解决了 PVP 判定（很聪明），但留了个洞：如果它一生成就脱离主人、也不占主人的配额，那玩家可以每天 5 次全召混乱体，把服务器变成野怪乐园。

补法（建议两条同时上）：
1. 混乱体**仍占主人的召唤配额**（生成时扣除，死亡/消散时返还）
2. 全服混乱体数量硬顶（建议 20 只），满了就不许再召

## 14. C 方案的五个必要配套（缺一个生态就崩）

PVP 全开放不是一个开关，是一整套机制。下面五条必须同时到位，少一条都会导致服务器一周内死掉。

### 14.1 新手保护：用空间替代时间（72 小时硬顶作废）

原方案的两个条件都有问题：按时间算，服务器开局会有半个月满街免战牌；按「首个稀有产物」算，玩家永远只造普通产物就能拿无限期免战牌。**两个条件都是在猜玩家的意图，而意图测不准。**

**最终方案：取消时间限制，改用新手村（安全区）+ 出界即解保。**

| 项 | 规则 |
|---|---|
| 保护区 | 新手村范围 **128 × 128**，村内**完全禁斗** |
| 解除条件 | **首次走出村界即永久解保**，不再有倒计时 |
| 保护期内 | 村内也不能攻击他人（双向，防小号肉盾） |
| 解保后 | 永久可回村，但村里给不了你想要的（见下） |

**为什么这个方案比时间硬顶好：保护期从「系统给的」变成「玩家自己选的」。** 玩家想安全就待在村里，想变强就自己走出去——不需要任何人告诉他"你的保护到期了"。

而且它顺手解决了时间方案最大的病灶：**缩在村里是有代价的**。村内禁稀有以上孵化、禁攻击型召唤、禁建筑生成，所以「永远不回野外」等于「永远造不出好东西」。**惩罚由规则自然产生，不需要额外机制。**

### 14.2 新手村的权限矩阵

| | 新手村（128×128） | 野外（无边界） |
|---|---|---|
| 战斗 | 完全禁斗 | 全开放 |
| 孵化 | **禁稀有以上** | 无限制 |
| 召唤 | **禁攻击型**（守护/混乱可） | 无限制 |
| 建筑 | 禁止生成 | 可建，受面积预算限制 |
| 准入 | 红名禁入、战斗标记期内禁入 | 任何人 |

**三条关键设计的理由：**

- **禁稀有以上孵化**：这是新手村的核心阀门。普通/稀有两个档位足够新人学会整套玩法，但拿不到能打的东西，玩家必然要出门。
- **禁攻击型召唤**：否则村里会出现「A 召恶龙打 B」的擦边玩法——禁斗判定管不住召唤物。
- **禁建筑生成**：否则新手村会被第一波玩家改造成私人要塞，后来的新人连站的地方都没有。

> **前哨站沿用同一套权限**（禁斗、禁稀有以上孵化、禁攻击型召唤、禁建筑生成），只是规模 64×64，且不提供主城级交易行。区别只在准入：前哨站**对红名开放**，主城不开放。详见 §14.4。

### 14.3 出界规则：随机传送（已确认）

**出村不是走出去，而是被传送出去。二选一：**

| | 安全传送 | 混乱传送 |
|---|---|---|
| 落点范围 | 村外 **50–300 格** | **500–2000 格** |
| 地形校验 | 逐格严检 | 仅判脚下 |
| 致死风险 | 零 | 低但真实 |
| 资源水平 | 普通 | **稀有概率 × 2.5** |
| 解锁条件 | 首次即可用 | **解保后才可选** |

**这个改动有个副作用值得单独说：「门口堵杀」问题直接消失了。**

我之前建议加 3 秒出界无敌，是为了防一群人守在城门、谁出去谁死。但玩家从此不从城门走出去，而是被随机扔到村外——**伏击失去了蹲守目标**。3 秒无敌仍然保留，但它的作用从「防堵门」降级为「防落点恰好有人」。

### 14.3.1 为什么混乱传送必须更肥

两条路线如果不做收益差，玩家永远选安全的那条——**混乱传送就成了一条没人走的死路**。

所以「距离 = 奖励」必须成立：**离村越远，矿脉和怪物密度越高**，这是 MC 地形生成的天然规律，不需要额外造机制。混乱传送把你扔到 2000 格外，本质是**把你扔到资源更富、但也更危险的地方**。

「稀有概率 ×2.5」是在这个天然规律上再加一层，确保混乱传送在收益上明显优于安全传送。**风险必须被定价，否则没人承担风险。**

### 14.3.2 落点校验（不做就是灾难）

**安全传送**必须逐条校验，任何一条不过就重摇：

- 落点方块与其上一格为空气，脚下 1 格为实心可站立
- 不含液体、岩浆、火、仙人掌、粉雪
- 不在悬崖边缘（以落点为中心 3×3 内无 ≥4 格落差）
- 不在他人领地 / 建筑范围内
- **半径 32 格内无其他玩家**（防落点即被杀）
- 重摇上限 20 次，全部失败则退化为「村口固定点」

**混乱传送**只保证「不会立刻致死」：

- 脚下有实心方块、身体 2 格为空气、不含岩浆
- 允许落在洞穴、树上、海底、悬崖边
- 允许落在其他玩家附近（这是风险的一部分）
- 重摇上限 5 次，全失败则给「村外 500 格固定点」

> 混乱传送**必须给「不会立刻死」的下限**。允许玩家被扔到危险处，但不能允许「传送落地即死」——那不是难度，那是 bug 感受。

### 14.3.3 单向通道（关键约束）

```
村内 → 野外：只能通过传送（二选一）
野外 → 村内：只能走回去
```

**传送是单向的，不能从野外传回村里。** 否则它会变成免费的逃命工具——被追杀了就点回村，红名机制和战斗标记全部失效。

走回去的成本，恰好就是「跑得越远越亏」的张力。玩家选混乱传送时会认真考虑：**这 2000 格，我回不回得来。**

### 14.3.4 回村卷轴（走不回来的解法）

有了单向传送，就必须给一个体面的回家方式，否则远征玩家会卡在远处：

| 项 | 规则 |
|---|---|
| 来源 | 村内 / 前哨站可购买，**用残损球结算**（1 个 = 1 张） |
| 效果 | 施法 3 秒后传送回最近的安全区 |
| 限制 | 战斗标记期内不可用；红名可用，但**只能回前哨站**，不能回主城 |

这一条顺带给了残损球一个**消耗出口**——之前它只能攒着合成，现在有了第二个用途，通货属性更完整。

### 14.3.5 进村与红名

```
进村：正常可进；但处于战斗标记（15 秒）时被弹开
红名：任何时候都不能进主城，只能进前哨站
```

**战斗标记期禁入直接复用 §14.5 的机制**，不需要新写逻辑。红名只能进前哨站这一点很重要——它让前哨站成为「红名的唯一落脚点」，而不是毫无意义的装饰。

### 14.3.6 首次出界的保护性限制

新人手滑点「混乱」被扔到 2000 格外、然后死掉——体验极差，且会直接导致退服。

所以：**混乱传送在解保前不可选**（灰显 + 提示「先熟悉野外」）。第一次出界强制走安全传送，且需要二次确认。

这不是限制玩家，是**把「第一次出门」这个高风险时刻的变量降到最低**。等他自己出过一次界、知道野外什么样，再让他选混乱。

### 14.4 前哨站网格（每 3000 格一个）

| 项 | 规则 |
|---|---|
| 主城 | **全服 1 个**，128×128，系统预置蓝图 |
| 前哨站 | **每 3000 格一个**，64×64，系统预置蓝图（缩小版） |
| 生成方式 | **按网格锚点按需生成**——玩家靠近时才生成，不预生成全世界 |
| 前哨站功能 | 安全区 + 孵化祭坛 + 合成台 + 回村卷轴购买点 |
| 前哨站**不提供** | 建筑生成、NPC 聚落、主城级交易行 |

**前哨站坚决不做「交通枢纽」。** 如果前哨站之间能互相传送，3000 格的间隔就没有意义了，整张地图会在心理上坍缩成一个小广场。它只是补给点——**安全、能造东西、能买到回家的路**，仅此而已。

**网格锚点算法（避免每次移动都遍历全部前哨站）**：

```
outpostChunkX = floor(playerChunkX / 187) * 187 + 93   // 187 区块 ≈ 3000 格
outpostChunkZ = floor(playerChunkZ / 187) * 187 + 93
```

玩家跨入新的区块格时检查该格锚点是否已生成，未生成则投放。这样前哨站数量与**玩家实际探索过的区域**成正比，不会因为世界无限而无限膨胀。

### 14.5 战斗标记：安全区的唯一例外

| 机制 | 规则 |
|---|---|
| 免战区 | 出生点半径 **64 格**，区内召唤物不能攻击玩家 |
| **战斗标记** | 造成或受到玩家伤害后 **15 秒**内，免战区保护失效 |

**只有免战区、没有战斗标记，等于给伏击者一个免费回城点**：打完就跑进圈里，受害者永远追不上。这两条是配套的。

> 注：新手村（128×128）与出生点免战区（64 格）重叠。建议**统一成一套 Zone 系统**，出生点作为新手村的中心，不再单独维护 64 格逻辑。

### 14.6 红名制度（惩罚已收敛为「禁入安全区」）

| 项 | 规则 |
|---|---|
| 触发 | 击杀其他玩家（**含召唤物代杀**） |
| 时长 | 30 分钟起，10 分钟内重复击杀递增，上限 6 小时 |
| **唯一核心惩罚** | **不能进入免战区**（进入即被弹开并提示残留时间） |
| 附加（轻微） | 头顶名字变红、全服可见的小地图标记 |
| 洗白 | 时间自然消退，或击杀袭城怪加速 |

**为什么「禁入安全区」一条就够了：** 原方案里的「死亡掉落翻倍」在新规则下已经失效——因为生成装备本就不再直接掉落（只掉残损球），翻倍没有对象可翻。而「禁入安全区」恰好是 PVP 玩家唯一真正的痛点：它会一点一点把红名玩家挤出安全区，逼他去野外生活。

这个惩罚很轻，但对进攻方是真实的：**你抢得越多，越回不了家。** 而且它不惩罚性过强，玩家不会因为一次冲动就退服。

**关键：召唤物代杀必须记在主人头上。** 否则玩家只要「不叫回恶龙」，就能无责任屠服。这一条是 PVP 能否自洽的分水岭，不能省。

### 14.7 混乱体的责任归属
混乱体击杀不计红名（因为它是野怪），但要在全服公告：**「某某 召唤的混乱体击杀了某某」**。

它杀不了责，但藏不住身份。用社会性惩罚替代规则惩罚 —— 这比强制红名更符合"混乱"的定位，而且不需要额外机制。

### 14.8 反制手段（必须有，否则被碾压的一方无路可走）

- **驱散**：净化祭坛/驱散卷轴，清除半径内所有非我方召唤物（有冷却）
- **召唤物互相攻击**：攻击型召唤物见到的敌对召唤物也会打 —— 这是最自然的平衡，用龙打龙
- **对玩家伤害衰减**：召唤物对玩家的伤害计算 **× 0.5**，避免一只传说级恶龙瞬间清场

## 15. 两个新暴露的硬冲突

### 15.1 战利品掉落 vs 配额刻印（新规则已自动消解）

原矛盾：装备绑「UUID + 刻印」，物品离手不释放；但 PVP 掉落要求装备能被抢走。抢 5 件就撑爆配额，不占配额就变成「杀一次拿一身神装」的最优解。

**新规则下这个矛盾直接消失了**：生成装备死亡时**不再掉落本体**，只掉落残损球。凶手拿到的从来不是「战力」，而是「一次重新摇奖的机会」。配额、刻印、战利品三者彻底解耦，不需要任何额外补丁。

这是这轮改动最大的收益：**它用一条规则消掉了一个原来需要三条规则才能压住的冲突。**

### 15.2 残损球：玩家获得的是次数，不是装备

| 项 | 规则 |
|---|---|
| 来源 | 刻印产物（装备/召唤物）阵亡，**30% 概率**掉 1 个残损球 |
| 不可直接使用 | 残损球**不能孵化**，只能作为合成材料 |
| 合成 | **3 个残损球 → 1 个正常精灵球**（工作台配方，任意稀有度混搭） |
| 新球额度 | **不占每日 5 次额度**，等于额外返还 1 次描述机会 |
| 新球稀有度 | **不得超过原料中的最高稀有度**，且比其最高值**降一档** |
| 归属 | 无主物品，任何人可捡、可交易、可存放 |

**为什么「降一档」是必须的：** 如果不降，玩家就能拿 3 个普通产物反复阵亡，攒 3 个残损球换 1 次机会——本质是「用 3 次换 1 次」，净亏 2 次，已经无套利空间。但再加「降一档」，就堵死了「用低稀有度原料合成高稀有度产物」这条最后的路。**合成是回收，不是升级。**

**为什么它对玩家仍然是正收益：** 因为残损球可以是**别人掉的**。捡 3 个别人的残损球，等于白嫖 1 次描述机会。这才是 PVP 的真正收益所在——**收益来自战场的遗留物，不来自击杀本身。** 这也顺带解释了为什么击杀不需要再给物质奖励。

### 15.3 三个必须现在就定的细节

**① 谁写的描述？**
合成出的新球由**合成者自己写描述**（否则残损球毫无意义）。但受两条限制：受 30 字上限约束、稀有度上限锁定为「原料最高稀有度降一档」。所以合成出来的球，本质是一张**有额度上限的空白券**。

**② 装备类产物也会掉球吗？**
会，但概率更低（**15%**）。原因是装备不会自然阵亡，只能靠耐久耗尽或被 PVP 击杀掉落——如果和召唤物同为 30%，玩家就会用「造便宜装备 → 打碎 → 换球」当做刷球流水线。**15% 让这条路亏本。**

**③ 幽灵球问题（必须处理）**
如果残损球的掉落判定绑在「实体/物品被销毁」事件上，那么扔进虚空、岩浆、`/kill`、区块卸载都可能触发掉落。必须在掉落前做**因果过滤**：

- 有效：被生物/玩家杀死、耐久耗尽、被驱散技能清除
- 无效：虚空、岩浆、`/kill`、区块卸载、管理员清除、超时 TTL 自然消散

**TTL 自然消散必须判无效**，否则玩家把宠召出来等它自己超时，就能零成本刷球。这一条不加，整个球经济当天崩掉。

### 15.4 球经济的净效果（自洽性校验）

| 路径 | 成本 | 收益 | 结论 |
|---|---|---|---|
| 自产自销 | 3 次额度 + 3 份材料 | 1 次额度 | **净亏 2 次**，无套利 |
| 捡别人的球 | 0 | 1 次额度 | 真收益，鼓励去战场捡东西 |
| 用便宜装备刷球 | 材料 + 装备耐久 | 15% × 1/3 次额度 | **亏本**，已堵 |
| 召宠等超时刷球 | 1 次额度 | 0（TTL 无效） | **已堵** |

**这张表能全部对上的前提是上面四条同时生效。少任何一条，球经济就会变成无限次数生成器。**

### 15.5 缺口：单机与纯 PVE 玩家永远拿不到球

上面整套推导有一个隐含前提——**「别人的残损球」存在**。单机、局域网、或开了沙盒但没人打架的存档里，这个前提不成立。

玩家的球只能靠自己的宠被打死才有 30% 掉落，再经 3 合 1，有效返还率只有 **10%**。也就是说单机玩家等于「球经济完全失效」。

**解法：把掉落来源和「谁杀的」解耦，按环境给两条独立概率。**

| 场景 | 掉落率 | 说明 |
|---|---|---|
| 被其他玩家 / 玩家召唤物杀死 | 30% | PVP 服主流路径 |
| **被野怪 / 袭城怪杀死** | **40%** | 单机与 PVE 的唯一来源，故意给得更高 |
| 装备耐久耗尽 / 被驱散 | 15% | 防刷 |

野怪掉落给到 40%，是因为它**没有「捡别人的球」这条补充路径**，必须靠自身掉落把返还率拉到 13% 左右。同时这也让「带着宠去打袭城战」变成一个有意义的行为：宠死了，你至少能捡回一点东西。

**顺带一个好处**：这条规则让单机和联机的核心循环变成同一个——**去打怪，宠会死，捡球，再造。** 联机只是在同一个循环上多了一层「可以从别人尸体边捡球」。

## 16. 建筑的三道校验（落地流程）

```
预览（玩家看到半透明轮廓，可旋转，3 秒内可取消）
   ↓
地形检测：目标区域内部非空气方块占比 ≤ 5%，且不含其他玩家的建筑领地
   ↓
面积预算：单座 ≤ 2000 方块，每人同时 ≤ 3 座，合计 ≤ 4000 方块
   ↓
落地
```

配套规则：
- **建筑领地**：每座建筑外围 **16 格**为领地，他人不可在此建造
- **拆除**：允许拆除，但拆他人建筑记红名（同 PVP）
- **覆盖保护**：绝不覆盖玩家手动搭建的方块，检测到就拒绝并提示具体冲突位置

## 17. 装备耐久系统（已确认：有耐久、不可修复）

### 17.1 耐久数值与扣减口径

| 稀有度 | 耐久（有效次数） | 折算寿命 |
|---|---|---|
| 普通 | 200 | 约 1 天 |
| 稀有 | 450 | 约 2–3 天 |
| 史诗 | 800 | 约 5 天 |
| 传说 | 1200 | 约 8 天 |

**扣减口径必须写死，否则玩家会钻：**

| 事件 | 扣减 |
|---|---|
| 攻击**命中**生物/玩家 | −1 |
| 空挥 | **−0** |
| 被生物/玩家打中（护甲类） | −2 |
| 挖方块 / 右键使用 | −0 |

空挥不掉耐久，是因为如果按「每次挥击」算，玩家会为了省耐久而在关键时刻不敢出手，手感会很差；如果反过来按「时间」算，挂机就会白白磨损。**按命中算最公平，也最好理解。**

### 17.2 耐久耗尽 → 残损的装备，不是凭空消失

装备坏了直接消失，玩家会认为「系统吞了我的东西」。改成变成「**残损的 X**」：

- 属性全部失效，不可装备，只留名字和外观作为纪念
- **可分解为材料**，返还 50% 的制造材料
- 分解时有 **15% 概率掉 1 个残损球**（与 §15.3② 同一条规则）

这让「装备报废」从被动损失变成主动决策——玩家会攒几件残损装备，专门拿去分解。

### 17.3 装备额度独立（已确认，但数值要下调）

**定案：装备不占每日 5 次，独立计数。**

| 类别 | 额度 |
|---|---|
| 召唤物 / 消耗品 / NPC | 每日 **5** 次 |
| 装备 | **每日 1 件**（独立，可累计，上限 3 件） |

理由是这两类性质根本不同：装备是**耐用品**（造一次用几天），召唤物是**消耗品**（用一次就没了）。混在一个池里，玩家在做完全不同性质的决策时互相挤占，心理账户会非常乱。独立之后认知变成「今天能造 5 个消耗品 + 1 件装备」，清晰且不憋屈。

**⚠ 但我上一轮建议的「每日 2 件」是错的，会严重过剩。算一下就看得出来：**

| 稀有度 | 耐久 | 日均命中 200 次时寿命 | 折算日均消耗 |
|---|---|---|---|
| 普通 | 200 | 1 天 | 1 件/天 |
| 稀有 | 450 | 2.3 天 | 0.43 件/天 |
| 史诗 | 800 | 4 天 | 0.25 件/天 |
| 传说 | 1200 | 6 天 | 0.17 件/天 |

两个槽位、按加权平均寿命 4 天算，**稳态日均消耗约 0.5 件**。给 2 件/天就是 4 倍过剩——多余的装备会被分解成材料，于是材料过剩、造物成本下降，稀缺性又被冲掉了。**这是连锁反应，不是单点问题。**

所以改成 **每日 1 件，且可累计、上限 3 件**：

- 1 件/天 = 2 倍于稳态消耗，留了充足余量给玩家挥霍和试错
- 可累计，所以「三天没上线」的玩家回来能连造 3 件，不会被卡
- 上限 3 防止长期不上线后一次性爆发，也防止 MMO 常见的「仓鼠玩家攒 30 件备用」

**同理，分解返还 50% 材料这个数值也要盯一下。** 如果装备产量是 1 件/天、平均 3 天报废一件，那每天会有约 0.33 件的材料回到池子里。这个回流量不大，50% 可以保留。但如果以后装备产量上调，这条必须同步下调到 30%。

### 17.4 一个必须提前避的技术坑

生成装备的 `max_damage` 是按稀有度动态写入的。**它只能在物品生成的那一瞬间写入一次**——之后再改会让原有的 `damage` 值百分比失真，玩家会看到耐久条突然跳变。

所以：**稀有度一旦确定，耐久上限就锁定，任何后续操作（附魔、升级、交易）都不得改 `max_damage`。** 这一点在实现时如果不注意，会变成大量「耐久条乱跳」的 bug 报告。

## 18. 残损球交易（已确认可交易）

### 18.1 它意外成了这套玩法的硬通货

3 个残损球 = 1 次描述机会，这是一个**天然的价值锚**。游戏内第一次有了可以给任何东西定价的单位。

建议直接承认它：**残损球就是硬通货**，UI 上按货币显示（像绿宝石那样）。

好处很直接：所有交易有了统一计价，玩家用「这东西值几个球」来衡量价值，而和平玩家（捡球商人）有了明确的商业模式——这正好给不想打架的人一条活路。

### 18.2 必须限制的三件事

**① 不可跨存档、不可带出服务器**
否则会催生现实货币交易（RMT）和工作室刷球。球必须绑定服务器 UUID，导出即失效。

**② 堆叠上限 16**
不限堆叠会让大商人囤积操纵价格。16 的上限让「囤球」变成需要仓库成本的行为，而不是无限仓库里的一个数字。

**③ 每次交易写日志**
谁、给谁、多少。不是为了监控玩家，而是 RMT 争议时你能举证。

### 18.3 球不占任何配额

要明确写进规则：**残损球既不占装备槽，也不占召唤配额**。否则玩家会不敢捡——怕捡了就造不了东西。

### 18.4 套利校验：3:1 让所有回收路径都亏本

有人会想到「A 造装备 → 送给 B → B 打碎 → 15% 掉球，重复 3 次换 1 次机会」。

成本是 A 的 3 次额度 + 3 份材料，收益是 B 的 1 次机会 —— **净亏 2 次**。即使沙盒模式材料无限，成本仍有 3 次额度，依然净亏。

**这就是整个球经济最坚固的地方：3:1 的兑换比例让任何形式的「造物 → 销毁 → 回收」都是亏本买卖，跟材料是否无限无关。**

## 20. 孵化时长与守坛机制

### 20.1 时长表：长度要匹配玩家在做什么

| 稀有度 | 基础时长 | 玩家实际行为 |
|---|---|---|
| 普通 | 8 秒 | 站着等，能忍 |
| 稀有 | 30 秒 | 开始想做点别的 |
| 史诗 | 2 分钟 | 一定去干别的 |
| 传说 | 10 分钟 | 当作一个任务来做 |

关键规律：**读条超过 30 秒，玩家就不会盯着看了。** 所以设计重点不是「让等待变短」，而是「让等待期间有事可做，且这件事和等待有关」。

### 20.2 并行孵化：球在背包里读条

球不需要放在祭坛上，**放在背包里就继续孵化**。玩家可以带着它去打怪、挖矿、跑图。

这解决了「读条等于原地罚站」的老问题。但它带来一个新取舍：球占一个背包格，而且**带着未孵化的球出野外是有风险的**（见 20.4）。

### 20.3 守坛加速：把等待变成主动选择

孵化祭坛 8 格内，孵化速度 **×2**；离开则恢复 ×1。

于是玩家每次孵化都要做同一个选择：

| 选择 | 收益 | 代价 |
|---|---|---|
| 守着祭坛 | 快一倍 | 这段时间不能去刷材料 |
| 带着去野外 | 正常速度 | 有死亡掉进度的风险 |

**两条路都不是错的** —— 赶时间就守坛，缺材料就带出去。这才是好的时间设计：让玩家权衡，而不是让他干等。

顺带，祭坛终于有了功能意义。之前它只是「生成入口」，现在它是**唯一能加速孵化的地方**，值得玩家在基地里专门造一个。

### 20.4 孵化期间死亡：进度减半，球不丢

带着未孵化的球死亡时：

- 球**不会掉落**（不像成品装备）
- 但**孵化进度减半**

**为什么不掉球**：球是「尚未实现的期待」，全损的挫败感远大于装备损坏——玩家会觉得「我白等了 10 分钟」。而进度减半传达的是「你被打断了」，可以接受，且仍然构成风险。

这也解释了为什么不该把「抢未孵化的球」做成玩法——**残损球已经承担了「抢球」这个功能**，再叠一层会让野外掉落变得太杂。

### 20.5 离线孵化：世界时间照走，但设 8 小时上限

玩家下线后球继续孵化，最多累计 **8 小时**。

完全不孵化，玩家会觉得「下线是浪费」；无限孵化，玩家可以「下线 3 天 → 上线领 15 个球」，把整个养成节奏打穿。

8 小时刚好覆盖「睡一觉」，是玩家对挂机的心理预期上限。超过部分不累计。

## 21. 袭城系统（生存压力模式的骨架，此前完全空白）

### 21.1 节奏

| 项 | 设定 |
|---|---|
| 周期 | 每 **3 个游戏日**（约 60 分钟现实时间）一波 |
| 预告 | 开波前 **5 分钟**全服公告 + 天空渐变为暗红 + 低沉音效 |
| 持续 | 8–12 分钟（含收尾） |
| 递增 | 每 5 波一个强度台阶，第 10 波为「灭世级」 |
| 跳过 | 沙盒模式可整波关闭；生存模式可调频率（慢 / 标准 / 快） |

**预告必须有 5 分钟。** 不是仪式感，是**给玩家回防的时间**。只有 30 秒的话，正在 2000 格外挖矿的玩家根本来不及回来，那一波等于白送。

### 21.2 强度必须按在线人数缩放（唯一不能省的一条）

固定强度在人数不同的服务器上表现完全不同（见上图）：2 人服第三波灭服，30 人服毫无压力。**同一个数值不可能同时适配两种规模。**

```
波次强度 = 基础强度(波次) × clamp(在线人数 / 10, 0.5, 4.0)
```

- 单人 / 2 人：**0.5** 倍（有下限，不至于毫无压力）
- 10 人：**1.0** 倍（**调参基准就是这一档**）
- 30 人：**3.0** 倍
- 上限 4.0，防止百人服无限膨胀

**奖励不参与缩放。** 奖励按人头各算一份，否则 30 人服每个人拿到的东西会少得可怜。

### 21.3 打谁：优先有在线玩家的区域

袭城怪的目标选择顺序：

1. 有在线玩家的建筑 / 基地
2. 主城（若无人防守，只有少量怪去骚扰）
3. **离线玩家的建筑：不拆，只做外观损伤**

第 3 条是必须的。如果离线玩家的家会被拆，玩家下线就会恐慌，长期会导致「必须挂机守家」这种最糟糕的结果。改成**「外观损伤、上线后免费修复」**——玩家看到墙破了几块，知道被打了，但核心资产没丢。

### 21.4 不参加会怎样

如果玩家躲野外就不挨打，那最优策略永远是「袭城期间一直在野外刷材料」。

所以：**袭城期间野外也刷怪**，但强度和密度低于主战场，且**不给稀有材料**。想拿稀有材料，必须回防。

### 21.5 奖励与失败

| 结果 | 后果 |
|---|---|
| 守住 | 每名参战者（造成 ≥5% 总伤害）获得稀有材料包，波次越高越好 |
| 部分失守 | 建筑损伤（可修），材料照发但减半 |
| 完全失守 | 建筑被拆一部分（核心结构不拆），**下一波强度 −20%** |

**「失败后下一波更弱」这条很重要。** 否则一次失守会导致连锁崩盘，玩家一旦发现「反正守不住」就直接放弃。

### 21.6 一个隐藏收益：循环在这里才真正闭合

袭城怪是**唯一稳定的稀有材料来源**，于是：

```
挖矿得普通材料 → 袭城怪掉稀有材料 → 造物 → 用造物守袭城 → 更高级的造物
```

它也天然解释了「为什么玩家必须变强」——不是为了打人，是为了下一波守得住。**这比 PVP 更能留住 PVE 玩家**，也是纯沙盒玩家愿意打开生存模式的原因。

## 22. 描述 → 解析 → 确认（核心交互链）

> ⚠ **v1.3 变更：本章的「解析」部分已被 §24 抽卡构筑取代。**
> 仍然有效的部分：22.5（输入/输出渠道）、22.6（失败路径给示例）、22.8 的本地计算思路。
> 已作废：22.0–22.4（解析三件事、确认卡、未识别词、约束点计数）—— 抽卡不需要解析，也就没有未识别词，稀有度改由词条点数决定。
> 保留它的原因是：**抽卡模式下「描述」降级为命名与权重引导**（见 §24.7），这条链里的渠道与手感结论仍可复用。

### 22.0 这条链真正在做三件事，不止一件

玩家以为它在「翻译」。实际上它要完成三件独立的事，而第三件最容易漏：

1. **翻译** —— 自然语言变成结构化产物
2. **暴露歧义** —— 在花材料之前，让玩家知道系统理解成了什么
3. **教会玩家怎么写** —— 把隐藏规则变成可见反馈

翻译错了只损失一次；**歧义不暴露，玩家会认为「这游戏听不懂人话」；规则不可见，玩家永远学不会「越细越强」。** 第 2、3 件才是决定手感的部分。

### 22.1 完整链路

```
快捷键打开输入框
  ↓ 实时：字数计数 / 材料预估 / 额度预估
输入 ≤30 中文字
  ↓
解析（规则引擎优先 → LLM 兜底 → 模板保底）
  ↓ 输出：标签集 + 约束点数 + 稀有度 + 未识别词清单 + 置信度
确认卡（3 秒内可读完）
  ↓ [确认孵化] [改写描述] [取消]
扣材料 → 生成球（进度 0%）
  ↓ 进度 <5% 可取消，全额退
进入孵化（见 §20）
```

### 22.2 确认卡：宁可少显示，也不能让信息过载

硬约束：

- 标签**最多 4 个**
- 数值信息**最多 3 行**
- 卡片总高不超过 260px

**为什么这么严：确认卡一旦超过 3 秒读完，玩家就会跳过它直接点确认。** 而一旦形成跳过习惯，这个环节就从「防错」退化成了「多一次点击」——纯负担，还得付 UI 成本。

所以确认卡只放四类信息，按重要性排序：

| 位置 | 内容 | 回答的问题 |
|---|---|---|
| 1 | 产物名 + 标签 | 这是什么 |
| 2 | 约束点数 → 稀有度 | **我写得好不好** |
| 3 | 未识别词提示 | **我有没有白写** |
| 4 | 材料消耗 + 今日额度 | 我付得起吗 |

### 22.3 未识别词提示：这条链的灵魂

玩家写「一把能斩断时间的刀」，词典里没这个词。系统会按「暗属性 + 高攻击」处理，然后必须明确告诉玩家：

> **「斩断时间」未识别，已按暗属性处理**

**这个提示把「系统的无知」显式化了。** 玩家看到它，立刻知道该改写成「暗属性的刀，攻击很高」。

没有它，玩家的结论是「这游戏听不懂人话」，然后放弃。有了它，玩家的结论是「哦，得换个说法」——**同一件事，一个导致流失，一个导致学习。**

置信度分三档：

| 档位 | 条件 | 表现 |
|---|---|---|
| 高 | 全部命中 | 无提示 |
| 中 | 有未识别词 | 黄色提示条 + 逐词列出 |
| 低 | 未识别占比 > 40% | 红色，直接建议改写，不给确认按钮 |

### 22.4 约束点计数：把「越细越强」变成可见规则

这一条直接落实最初的设计意图。

```
约束点 = 命中的元素 + 形态 + 效果 + 程度
```

| 约束点 | 稀有度 |
|---|---|
| 1 | 普通 |
| 2–3 | 稀有 |
| 4–5 | 史诗 |
| 6+ | 传说（另需材料支撑） |

确认卡上显示「**3 个约束点 · 稀有**」，玩家立刻明白「多写一个效果就能升级」。

**这是整套玩法最重要的教学时刻，而它免费发生在每一次生成里。** 不需要教程、不需要提示文案——玩家自己会做实验。

### 22.5 输入走聊天框，输出走独立 GUI

聊天框输入最快（已定），但多人服有个物理问题：20 个人同时提交，频道会被刷屏。

所以分开：

| 环节 | 渠道 |
|---|---|
| 输入 | 聊天框（快捷键触发独立输入模式） |
| 确认卡与结果 | **独立 GUI，不上聊天频道** |
| 全服播报 | 仅「某某 造出了 传说级 XX」，且**玩家可勾选是否公开** |

最后一条很重要：有些玩家不想被打扰，也不希望别人知道自己在造什么（尤其是造恶龙准备打人）。**默认不公开，由玩家自己选择炫耀。**

### 22.6 失败路径必须给可点击的示例

解析完全失败（「asdfgh」「？？？」）时：

```
没能理解这段描述。
试试「元素 + 形态 + 效果」的结构：

[ 火焰巨剑，能吸血 ]   [ 冰霜长弓 ]   [ 加速的苹果 ]
```

三个示例是**可点击的**，点了直接填进输入框，玩家还能改。

这个设计的意义：**把「教玩家怎么玩」嵌进失败路径里。** 玩家不会主动读攻略，但一定会看报错。

示例库要按玩家当前状态筛选（材料够、额度够、稀有度够得着），否则点了也用不了，反而更挫败。

### 22.7 撤销窗口优于二次确认

确认即扣材料。但玩家一定会手滑。

**规则：球生成后，孵化进度 <5% 时可取消，材料与额度全额返还。**

5% 对应普通产物约 0.4 秒、史诗约 6 秒——足够长到「发现自己选错了」，又短到不能用来试探。

**为什么不做「确认前再确认一次」**：那会变成两次点击，且玩家会习惯性连点两下，等于没防住。**撤销窗口不打断流程，只在真出错时生效**，这是更好的错防设计。

### 22.8 解析预算：规则引擎无限，LLM 每天 20 次

| 解析方式 | 预算 |
|---|---|
| 规则引擎 | **无限**（毫秒级，本地计算） |
| LLM 兜底 | **每玩家每天 20 次** |

20 次远高于正常需求（5 次生成 + 15 次改写尝试）。设上限是为了防两类人：写 200 个奇怪描述**测试边界**的玩家，以及专门用无意义输入**烧你 token** 的人。

### 22.9 一个必须现在就埋的埋点

记录每一次「确认卡显示 → 玩家点了改写」的行为。

这是最直接的解析质量指标：

- 改写率整体偏高 → 解析不准
- **某个词被反复改写 → 那个词的映射就是错的**

**没有这个埋点，你永远不知道规则引擎哪里烂**，只能靠玩家抱怨来猜。这是整条链里投入产出比最高的一个埋点。

## 24. 抽卡构筑系统（v1.3 新增，取代自然语言解析）

### 24.0 这不是加玩法，是换掉整个生成内核

原来的链路是「自然语言 → 结构化」。最重的技术债全在这里：规则引擎、LLM 兜底、未识别词映射、置信度分档、输出校验、越狱防护。

抽卡直接给出结构化词条，**上面这一整层可以删掉**。这不是优化，是架构级的减法。

| 项目 | 解析方案（原） | 抽卡方案（新） |
|---|---|---|
| LLM 依赖 | 必需（兜底） | **完全不需要** |
| 离线可行性 | 降级链（残缺） | **原生完整** |
| 生成延迟 | 200ms–3s | **0ms（纯本地查表）** |
| 单次成本 | 有（token） | **0** |
| 数值可控性 | 需事后校验裁剪 | **天然可控（数值来自卡表）** |
| 内容安全 | 需词表 + 白名单 + Schema | **天然安全（只有预置词条）** |
| 工程量 | 基准 100% | **约 60–65%** |

之前列的三条重型风险（AI 建模、资源包重载、双平台适配）现在只剩外观一条。**这是整个需求里最省工作量的一次改动。**

### 24.1 抽取层级

| 层 | 名称 | 内容 | 5 张里有什么 |
|---|---|---|---|
| 0 | 基调 | 装备 / 消耗品 / 召唤物 | 直接三选一（不做随机） |
| 1 | 载体 | 枪 / 剑 / 弓 / 法杖 / 护符 / 苹果 / 龙 / 兽 | 受基调约束（装备只出装备载体） |
| 2 | 元素 | 雷 / 火 / 冰 / 毒 / 光 / 暗 / 岩 / 风 | 品质随机 |
| 3 | 属性 | 射速 / 伤害 / 暴击 / 穿透 / 吸血 / 护甲 … | 受载体约束（枪不出护甲） |
| 4 | 效果 | 连锁 / 爆炸 / 击退 / 感电 / 残影 | 品质随机，强联动 |
| 5 | 命名 | 玩家输入（≤12 字）或系统拼装 | 不计入点数 |

**「受上层约束」这一条是整个系统的地基。** 没有它，玩家选枪却抽到「跳跃高度 +3」，会立刻认定系统是坏的。加了之后，5 张牌永远「合理」，只是不一定「最优」——这才是选择的意义。

### 24.2 难度定义必须改写（这是与最初设定的冲突）

最初设定：**描述越仔细 → 越难 → 越久。**
抽卡里玩家不写字，这个因果断了。必须换成：

```
难度 = 已选词条点数总和
点数：白 1 · 蓝 2 · 金 4 · 红 7
稀有度预算：普通 4 ｜ 稀有 8 ｜ 史诗 16 ｜ 传说 28
```

界面上常驻一行：**「点数 11 / 16 → 史诗」**。玩家一眼就知道还差多少、还能选几张。

这个定义比原来的「约束点数」更准，因为：

- 原来的约束点需要 NLP 判定（易错、不可预期）
- 现在的点数**直接印在卡面上**（零歧义）
- 超预算时，高点数卡**直接变灰不可选**，从机制上杜绝了「造出超模产物」

**这是一种比任何校验都干净的安全边界。**

### 24.3 五张牌的成本结构（防「永远选最高品质」）

如果白弱红强，玩家必然无脑点红卡，5 选 1 退化成「点最左边那张亮的」。三个约束同时上：

**① 每层品质分布固定**：必出 1 高、1 中、3 低（金/蓝/白，或红/金/白×3），高品阶概率随层数递增。

**② 高品阶必带代价。**

| 品阶 | 强度 | 代价 |
|---|---|---|
| 白 | 基准 1.0× | 无 |
| 蓝 | 1.6× | 无 |
| 金 | 2.5× | 小代价：耐久 −20% 或材料 +1 |
| 红 | 4.0× | **真代价**：移速 −10% / 不可修复 / 占 2 个装备槽 / 孵化 +50% |

红卡的「孵化 +50%」尤其重要——**它把「越强越久」这条最初设定重新接回来了**，只不过从「描述长度决定」变成「词条强度决定」。

**③ 同层不重复词条**：5 张牌不出现同类，避免「三张都是伤害」这种无效抽取。

### 24.4 协同：让 5 选 1 变成真决策

每条词条记录与其它词条的 `synergy` 关系，抽到时直接显示：

```
[ 感电 ] 与已选【雷】联动：感电概率 +15%
[ 吸血 ] 与已选【暴击】联动：暴击回血 ×2
[ 穿透 ] 与已选【高射速】冲突：单发伤害 −20%
```

**必须同时显示协同与冲突。** 只显示增益，玩家会认为系统在推销；显示冲突，玩家才会计算「要不要为了联动牺牲单发伤害」。

没有这一层，抽卡就只是「按数字排序」；有了它，才有构筑。

### 24.5 三个必需的控制旋钮

**① 中途定稿**：抽到第 3 层就可以结束（点数低 → 稀有度低 → 孵化快）。不是必须抽满 6 层。

**② 重抽（reroll）**：对当前层不满意，花 **1 个残损球** 重开 5 张。同一层连续重抽次数越多，代价递增（1 → 2 → 3 球）。

> 这里残损球找到了最有说服力的用途，比「回村卷轴」更贴合它的本质——**它本来就是「一次重新来过的机会」**。

**③ 保底**：连续 2 层未出蓝以上，第 3 层必出蓝 +；连续 4 层未出金以上，第 5 层必出金 +。

没有保底，极端倒霉的玩家会连续抽到 6 层白卡，产出一件毫无价值的东西，还白等了 30 秒——**这是抽卡游戏流失率最高的场景**。

### 24.6 关键决定：抽卡不消耗额度，只有「定稿」才消耗

这条**必须现在定，不然整个系统会废掉**。

原规则是每日 5 次生成额度。在抽卡制下，玩家每次抽卡都等于在赌——**如果抽卡就扣额度，玩家会不敢抽**，5 次额度变成 5 次赌博机会，赌输更挫败。抽卡游戏最怕的就是「不敢试」。

改成：

| 行为 | 消耗 |
|---|---|
| 抽卡、换一套新牌重来 | **0**（不扣额度、不扣材料） |
| 同层重抽（保留已选） | 1 残损球，递增 |
| **定稿并孵化** | **扣 1 次额度 + 材料** |

于是稀缺性从「抽卡次数」转移到「定稿次数」，而抽卡的探索乐趣被完整保留。玩家可以玩一下午抽卡试试能凑出什么，但一天只能真正产出 5 件。

**这一条同时消掉了一个隐患**：之前 22.7 讨论的「撤销窗口」不再需要了——因为定稿前一切都可以自由重来，不存在手滑。

### 24.7 描述降级为「命名 + 权重引导」（保留情感价值）

问题：纯抽卡会让玩家觉得「这不是我造的东西，是系统发的东西」。解法是保留描述，但只让它做两件低风险的事。

| 用途 | 机制 | 技术成本 |
|---|---|---|
| **命名与风味文本** | 玩家输入名字（≤12 字），系统生成 1 句 lore | 零（纯文本，可本地模板） |
| **权重引导** | 写「雷」，雷系词条出现概率 ×2.5；写「枪」，枪载体 ×3 | 零（关键词匹配） |

第二件事是**这套设计的精髓**：描述不再决定「是什么」，只决定「更可能是什么」。

- 写对关键词 → 更容易抽到想要的 → 有正反馈
- 写错或写怪 → 只是没加成，**不会生成错误产物**
- 完全离线 → 关键词表就是本地字典，不需要任何模型

对比原方案：原方案里解析错会直接产出一个错的东西（玩家骂人）；现在最坏情况只是「权重没加成」（玩家觉得可惜，但结果仍然合理）。

**失败模式从「错误」降级为「没加成」，这是抽卡方案最被低估的优势。**

### 24.8 与已有系统的接口

| 已有系统 | 接口方式 |
|---|---|
| 孵化时长（§20） | 稀有度由词条点数决定 → 直接查时长表；红卡的「+50%」在此生效 |
| 装备耐久（§17） | 无论抽到什么，`max_damage` 仍由稀有度定，红卡减免在此生效 |
| 配额（§10） | 定稿时按基调占对应槽位，机制不变 |
| 残损球（§15） | 新增用途：同层重抽 1 球 / 递增。**球的价值锚从「1/3 次生成」扩展到「1 次重抽」，更硬** |
| 战力预算 | 原 `AttrCost`/`BudgetResolver` 逻辑可直接复用，输入从「解析结果」换成「已选词条列表」 |
| 建筑 | **不受影响**，仍走模块化拼装（§16），与抽卡是两套 |
| AI 建模 | **受影响，且是利好**：词条是预置的，外观可以按「载体 × 元素」预先做好，**不需要临时生成** |

最后一条值得展开：原先 AI 建模是为了「生成玩家描述的那个东西」。现在产物由预置词条组合而成，**外观可以直接映射到「载体模型 + 元素配色 + 品质特效」**，全部预生成。**抽卡方案把 AI 建模这条最贵的路径也一并省掉了。**

### 24.9 内容成本

需要的卡表规模：

| 表 | 条目数 | 工作量 |
|---|---|---|
| 载体 | 18（6 装备 + 5 消耗品 + 7 召唤物） | 小 |
| 元素 | 9 | 小 |
| 属性词条 | 约 120（含品质变体） | 中 |
| 效果词条 | 约 90 | 中 |
| 协同/冲突关系 | 155 条（去重后实测） | **大（最费时）** |
| 外观映射（载体×元素） | 18 × 9 = 162 套 | 中（可程序化染色） |

**总组合数**：3 × 18 × 9 × 120 × 90 ≈ **52 万种**，足够玩家玩很久不重样。

**成本性质变了**：从「美术 + AI 管线 + 资源包工程」变成「纯策划填表」。**不需要美术，不需要建模，不需要深度学习。** 一个策划两周能填出可玩版本。

### 24.10 三个新增风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **抽卡疲劳** | 每次生成都要点 5–6 次，一天 5 次就是 30 次点击 | 提供「快速生成」：全随机自动选（牺牲最优性换速度），老玩家会用 |
| **最优解固化** | 玩家社群会算出「雷 + 高射速 + 连锁 + 吸血」是唯一答案，之后所有人一样 | 协同要给「多峰」而非单一最优；每个载体要有自己的强势组合 |
| **抽卡感过强 = 赌博感** | 红卡概率若设计成 1%，会诱发氪金联想和挫败 | **红卡概率给到 8–10%**，且保底明确。宁可平庸也不要留下「这是个抽卡手游」的印象 |

第三条是**气质问题，不是数值问题**。一个买断制的 MC 小游戏，如果让玩家感到「像手游抽卡」，口碑会直接崩。所以：**不做付费抽卡、不做限时概率、红卡概率对玩家公示**。

## 25. 定向卡（v1.4 新增）

### 25.0 它补的是抽卡系统最大的风险

§24.10 列的三个风险里，「抽不到想要的」是最会劝退人的：玩家想造龙，连抽三层全是剑、弓、兽、晶簇，第六层还是没龙。这种体验不是「手气差」，是「我想要的在这个游戏里根本不存在」。

定向卡把这个问题从「赌运气」变成「投资源」，机制上是干净的：**没有人被剥夺获取权，只是要付出代价。**

### 25.1 最关键的一条：定向保「类型」，不保「强度」

```
定向卡保证：这一层 5 张里一定有【龙】
定向卡不保证：这张龙是红卡
```

这是整个机制能不能成立的分水岭。

如果定向连品质一起保（「一定有红龙」），那玩家买到的就是产物本身，抽卡退化成点菜，前 4 层全部失去意义。

保类型不保强度之后，玩家面对的仍然是真选择：

```
[ 白·龙 ]  [ 蓝·弓 ]  [ 金·晶簇 ]  [ 白·兽 ]  [ 蓝·法杖 ]
   ↑ 想要的              ↑ 更强
```

**「要想要的，还是要更强的」——这个选择才有意思。** 而且它天然自平衡：定向卡用得越多，得到的产物越「对味但平庸」，玩家会自己学会取舍。

### 25.2 只作用于层 1 和层 2（工程量硬约束）

| 层 | 是否支持定向 | 理由 |
|---|---|---|
| 层 1 载体 | **支持** | 18 个载体，最有价值，卡表小 |
| 层 2 元素 | **支持** | 9 个元素，卡表小 |
| 层 3 属性 | 预留 | 120+ 词条，做出来就是 120 张卡 |
| 层 4 效果 | 预留 | 90+ 词条，同上 |
| 层 5 命名 | 不适用 | 玩家本来就自己写 |

层 3/4 不是设计上不该做，是**做出来会产生 200+ 种定向卡，掉落表和 UI 都会爆**。先做 27 种（18 载体 + 9 元素），已经够覆盖玩家的「我想要个龙 / 我想要个雷」这类需求。

数据结构留好 `target_layer` 字段，以后要扩只是填表。

### 25.3 时序约束：必须在抽卡**之前**使用（这是必须堵的漏洞）

如果允许「先看这 5 张牌，再决定要不要用定向卡」，那定向卡就变成了**免费保底**：没龙就补龙，有龙就留着下次用。

损失厌恶会让玩家**每次都等看完再决定**，于是定向卡的实际成功率接近 100%，随机性被彻底买穿。

必须写死：

```
层 0 选基调 → 【此时选择是否使用定向卡】→ 层 1 抽卡 → 层 2 …
```

**用完即消耗，抽出来之后不能用、不能撤、不能回收。** 玩家的决策从「结果不好再补救」变成「先押注，再看结果」——这才有赌的张力。

同理，**定向卡也不能预览本层池子**。否则玩家会挑「这一层本来没什么好卡」的时候用定向卡，把随机性的坏处全部规避掉。

### 25.4 与保底、重抽的交互（三条都要写死）

**① 定向卡占用的卡位，品质照常 roll。**
定向只决定「这一格是谁」，不决定「这一格多好」。品质 roll 与词条 ID 完全正交，实现上是两个独立的随机步骤。

**② 保底与定向可叠加，不冲突。**
保底约束的是品质（第 3 层必蓝+），定向约束的是词条（这一层有龙）。两者正交，所以「定向 + 保底」自然产出一张**蓝以上的龙**——这是玩家最想要的组合，也应该是。

**③ 重抽不丢定向。**
玩家用了龙定向卡，注入后对其它 4 张不满意，花球重抽当前层 → **龙还在**，只重 roll 其它 4 张。

这一条不写死会出大问题：玩家会怕「重抽把定向卡浪费了」，于是抽到不理想的组合也不敢重抽，**整条重抽链路直接废掉**。定向卡是整层的修饰符，不是一次性道具。

### 25.5 来源：不做解锁门槛，改用「材料合成 + 掉落」双轨

**定案：取消图鉴解锁。定向卡是可直接获得的消耗品，拿到就能用，没有任何前置条件。**

好处很实在：新玩家第一天就能用上，不用先肝 10 次；机制的理解成本降到零；存档也简单了（纯物品，不需要账号级状态）。

但要补两个被删掉的东西：**产量控制** 和 **长期目标**。

#### 产量控制：用材料成本替代解锁门槛

解锁门槛原本兼职做「产量闸门」——要收集 10 次才解锁，等于天然限量。删掉后若只靠掉落，产量完全取决于掉率，一旦调高，随机性就会被买穿。

改成双轨：

| 来源 | 做法 | 定位 |
|---|---|---|
| **合成（主）** | 祭坛用 **3 份稀有材料** 合成 1 张指定定向卡 | 稳定、可预期、玩家主动 |
| **袭城掉落（辅）** | 袭城怪随机掉落**未指定**的通用定向卡，开卡时再选载体/元素 | 惊喜、稀缺 |
| **PVP 掠夺** | 从阵亡玩家背包中获得，量小 | 战场收益 |
| 交易 | 可交易（不跨存档、写日志、堆叠上限 16） | 流通 |

**为什么锚在「3 份稀有材料」：** 稀有材料来自袭城，是这套玩法唯一的主循环硬通货。定向卡的合成成本约等于**多造一件史诗产物的材料量**，于是玩家面对一个清晰的取舍：

> 「同样的材料，我是造一件随机的史诗，还是定向造一件对味但可能平庸的史诗？」

**这个取舍本身就是玩法**，而且它把定向卡牢牢绑回主循环——想定向，就得多打袭城。材料是天然的通胀阀门，比任何解锁门槛都好调。

合成制还有个额外好处：**定向卡从「碰运气的掉落」变成了「可预期的商品」**，玩家能规划，交易市场也能定价。

#### 长期目标：图鉴降级为纯展示

删掉解锁门槛等于拆掉了原先那个「36 天目标系统」。**这个缺口需要填，否则玩家守完几波袭城后没有新驱动。**

建议的补偿（成本低、不动已定机制）：

| 方案 | 成本 | 强度 |
|---|---|---|
| **图鉴降级为收集册**：只记录造过什么、造了多少，不做解锁，给称号与展示 | 低 | 中（荣誉驱动） |
| 袭城波次推进（§21 已定，第 10 波灭世级） | 已有 | 强（压力驱动） |
| 载体熟练度：用某载体造 N 次 → 该载体**品质下限 +1** | 中 | 强（成长驱动） |

我倾向 **收集册 + 袭城波次** 先上，熟练度留 P2。理由是熟练度虽然有效，但它本质上是「图鉴门槛」的变体，你可能同样不想要。

### 25.6 两条硬约束

**① 每件产物最多用 1 张定向卡。**
6 层全定向 = 点菜，抽卡当场死亡。1 张是「修正」，2 张就开始变「替代」，3 张以上就是纯构筑，随机性归零。

**② 定向卡不占配额、不占额度。**
它只是修饰符，不进入 §10 的配额计算，也不消耗每日定稿次数（定稿时才扣）。否则玩家会因为「用了定向卡还占额度」而不愿用。

### 25.7 三个新风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **定向卡通胀** | 没有解锁门槛后，产量只剩合成成本与掉率两道闸；一旦放宽，每件产物都能定向，随机名存实亡 | 合成成本锚在「一次史诗造物的材料量」；通用卡掉率严格控；另设**每日使用上限 3 次** |
| **新老玩家体验断层** | 老玩家囤了大量定向卡，新玩家全靠随机 | 定向卡**只保类型不保强度**，老玩家优势是「对味」不是「更强」；另建议**新手引导送 1 张**，让新玩家第一天就理解机制 |
| **与描述权重引导功能重叠** | 写「龙」→ 龙 ×2.5（§24.7），和定向卡「必定有龙」看起来是同一件事 | 不算重叠，是**同一梯度的三档**，见下 |

**「每日使用上限」和「解锁门槛」必须分清：**

- 解锁门槛 = 要做前置任务/收集才能用 → **已删，不做**
- 使用上限 = 一天最多用几次 → **建议保留 3 次**，它不阻止任何人使用，只防产量失控

若连上限也不要，替代方案是把合成成本提到 **5 份稀有材料**，用价格而非次数控量。这条路更自由，但对经济数值的调参要求高得多。

### 25.8 三档确定性：免费 / 消耗 / 稀缺

「我想要龙」这件事现在有三个价位的解法：

| 档位 | 手段 | 保证 | 代价 |
|---|---|---|---|
| **软指定** | 描述里写「龙」 | 龙出现概率 ×2.5 | **免费**，只是概率 |
| **硬指定** | 定向卡 | **必定出现 1 张** | 3 份稀有材料 或 1 张掉落卡 |
| **重开** | 残损球重抽 | 换一批新牌 | 1 球，递增 |

三档的价格梯度刚好匹配三种心态：**「试试看」→「我要这个」→「这批都不行，再来」。**

而且它们分别消耗三种完全不同的资源（免费关键词 / 稀有材料 / 残损球），互不挤占。**一个玩家可以同时用三档，也可以只用免费那档玩到底。**

### 25.9 与已有系统的接口

| 系统 | 接口 |
|---|---|
| 配额（§10） | 定向卡不占配额，定稿时按基调正常占槽 |
| 额度（§24.6） | 定向卡不占额度，只有定稿扣 |
| 残损球（§15） | 互不影响。球管「重抽」，卡管「定向」，两类资源不互相兑换（**防止套利：1 球 ≠ 1 定向卡**） |
| 稀有材料（§21） | 合成消耗 3 份，与造物争夺同一资源池 → **这是定向卡的主要成本闸门** |
| 建筑（§16） | 不适用，建筑走模块拼装 |
| 存档迁移 | **纯物品，无账号级状态**。这是删掉图鉴门槛带来的实际简化——不需要额外的解锁表，也不会出现「重装后解锁丢失」这类问题 |

## 26. v1.5 定案（用户已确认）

| 项 | 定案 |
|---|---|
| 定向保什么 | **只保类型，不保强度**（保证有龙，不保证是红龙） |
| 使用时机 | **必须在抽卡前使用**，抽出来之后不能用、不能撤、不能回收 |
| 解锁门槛 | **不做**。定向卡是可直接获得的消耗品，无任何前置条件 |
| 产量控制 | 改由**材料成本 + 掉率**承担（合成 3 份稀有材料 / 袭城掉落 / PVP 掠夺 / 可交易） |
| 图鉴 | 解锁功能取消；**降级为纯收集册**（只记录与展示，不做门槛） |
| 每件产物用量 | 最多 1 张 |
| 配额与额度 | 定向卡不占配额、不占额度 |

### 26.1 这次删减带来的三个连锁变化

**① 技术实现变简单了。** 定向卡退化为纯物品，不需要账号级的「解锁状态表」，也不会出现「重装后解锁丢失」「同一账号多存档解锁不同步」这类问题。**这是一次净减法。**

**② 但产量闸门少了一道。** 原来的解锁门槛兼职做限量，现在只剩合成成本与掉率。所以**合成定价（3 份稀有材料）必须当成核心数值来调**，它承担了原来门槛的全部职责。

**③ 长期目标出现缺口。** 原先「18 载体 × 10 次 ≈ 36 天」的目标系统随图鉴门槛一起没了。**必须补一个，否则玩家守完几波袭城后没有新驱动。** 建议的补偿顺序：

```
收集册（低成本荣誉系统） → 袭城波次推进（已有） → 载体熟练度（P2，本质是门槛变体，慎用）
```

### 26.2 v1.6 追加定案（用户已确认）

| 项 | 定案 |
|---|---|
| 层数 | **可中途定稿**（抽完载体即可收，也可抽满 4 层） |
| 额度 | **抽卡不扣额度，只有定稿扣**（稀缺性放在定稿次数） |
| 定向卡每日上限 | **保留 3 次**（频率限制，不是解锁门槛） |
| 长期目标 | **用收集册补**（袭城波次为压力轴） |

### 26.3 ⚠ 一处必须修正的口径：「6 层」其实是 4 层可抽

前两轮我一直写「6 层满配」，这个说法不准确，现在统一：

| 层 | 名称 | 是否抽取 | 说明 |
|---|---|---|---|
| 层 0 | 基调 | **否** | 装备 / 消耗品 / 召唤物，手动三选一 |
| 层 1 | 载体 | 是 | 枪、剑、弓、法杖、龙、兽… |
| 层 2 | 元素 | 是 | 雷、火、冰、暗… |
| 层 3 | 属性 | 是 | 射速、伤害、暴击、吸血… |
| 层 4 | 效果 | 是 | 穿透、连锁、击退… |
| 层 5 | 命名 | **否** | 玩家自己输入 |

**真正可抽的是 4 层**。这个修正直接影响预算表：4 层全红 = 28 点，所以传说级预算恰好是 28，不多不少。

## 27. 卡表结构定义（数据地基）

这一章是整个抽卡系统唯一的硬地基。表结构定死之后，抽卡逻辑、UI、保底、点数校验、定向注入全部可以照着写；表一旦反复改，上面所有东西都要返工。

### 27.1 五个核心实体

```
Affix        词条本体的定义（静态数据，随版本走）
Tier         品质档位与换算规则（静态，全局唯一）
AffixTier    某个词条在某品质下的具体表现（动态组合表）
SynergyLink  词条之间的协同 / 冲突关系（静态，双向）
TargetCard   定向卡定义（静态）
DraftSession 一次抽卡的运行时状态（动态，每人一份）
```

### 27.2 Affix —— 词条本体

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一键，命名规范 `层.类别.名`，如 `elem.lightning` |
| `layer` | enum | `CARRIER` / `ELEMENT` / `ATTRIBUTE` / `EFFECT` |
| `name` | string | 中文显示名 |
| `base_type` | enum | 基调用：`EQUIPMENT` / `CONSUMABLE` / `SUMMON` / `ANY` |
| `carrier_allow` | list | 只在哪些载体下出现（空 = 全载体可用） |
| `carrier_deny` | list | 在哪些载体下不出现（如枪禁「跳跃高度」） |
| `element_allow` | list | 只在哪些元素下出现（如「感电」只给雷） |
| `excludes` | list | 互斥词条 id（如雷与火） |
| `weight` | int | 基础出现权重，默认 100 |
| `appearance_key` | string | 外观映射键，用于生成资源包槽位 |

**关键设计：`carrier_allow` / `carrier_deny` 是「受上层约束」这条规则的落地方式。** 没有这两个字段，玩家选了枪会抽到「跳跃高度 +3」，整场崩掉。

### 27.3 AffixTier —— 品质变体（不是四张卡，是一条的四档）

同一词条在不同品质下是**同一张卡的不同强度**，不是四张独立的卡。这样卡表规模是 1 而不是 4。

| 字段 | 说明 |
|---|---|
| `affix_id` | 指向 Affix |
| `tier` | `WHITE` / `BLUE` / `GOLD` / `RED` |
| `points` | 点数：白 1 / 蓝 2 / 金 4 / 红 7 |
| `magnitude` | 强度系数：1.0 / 1.6 / 2.5 / 4.0 |
| `drawback` | 代价（仅金/红有），见下 |
| `desc_template` | 文案模板，如 `吸血 {value}%` |

**drawback 的枚举**（金卡取一项小的，红卡取一项真的）：

| 类型 | 含义 | 适用 |
|---|---|---|
| `DURABILITY_PCT` | 耐久 −20% | 装备 |
| `MATERIAL_EXTRA` | 材料 +1 | 全部 |
| `HATCH_TIME_PCT` | **孵化时长 +50%** | 全部（把「越强越久」接回来） |
| `MOVE_SPEED_PCT` | 移速 −10% | 全部 |
| `UNREPAIRABLE` | 不可修复 | 装备 |
| `SLOT_COST_2` | 占 2 个装备槽 | 装备 |

### 27.4 抽取池过滤规则（层 × 维度）

| 层 | 过滤条件 |
|---|---|
| 层 1 载体 | `base_type` ∈ 基调；`layer = CARRIER` |
| 层 2 元素 | `layer = ELEMENT`；排除与已选载体互斥的元素 |
| 层 3 属性 | `layer = ATTRIBUTE`；`carrier_allow` 含当前载体；`element_allow` 含当前元素（若限定） |
| 层 4 效果 | `layer = EFFECT`；过滤条件同层 3，另排除与已选词条 `excludes` 冲突的 |

**池内不能抽空。** 若过滤后候选 < 5 个（极窄载体组合可能发生），规则是：先放宽 `element_allow`，再放宽 `carrier_allow`，最后才允许重复出现同词条的不同品质。**绝不能出现「这层只有 3 张牌」的界面。**

### 27.5 抽取算法（伪代码）

```
draw(layer, session):
    pool = filter(layer, session.picks)            # 按 27.4 过滤
    pool = exclude_selected(pool, session.picks)   # 不重复
    cards = roll_quality(pool, quality_dist(layer))# 1高 1中 3低
    cards = enforce_budget(cards, session.remaining)
    if session.targeted.contains(layer):
        cards[random_index] = session.targeted.affix  # 定向替换，位置随机
    cards = apply_guarantee(cards, session)        # 保底
    return cards
```

三个必须写进算法的细节：

**① `enforce_budget`：至少保证 2 张卡买得起。**
若剩余点数为 2，而 roll 出来是 1 金 1 蓝 3 白（金 4 点不可选、蓝 2 点可选），只有 4 张可选，勉强够。极端情况下若只有 1 张可选，**把超预算的卡降一档重 roll**，直到满足 2 张。

不加这条，玩家在最后一层会面对「五张牌四张变灰」的绝望感——不是难，是坏。

**② `apply_guarantee` 与定向正交。**
保底约束品质，定向约束词条 ID，两者互不干扰。定向占用的卡位同样参与保底判定，所以「保底 + 定向」能产出「必定是蓝以上的龙」。这是玩家最想要的组合，也应该是。

**③ 随机数必须 `seed` 化并落日志。**
一次抽卡全部用同一个 session seed 派生。玩家投诉「我抽了十次都没出红卡」时，你能拿日志自证是概率问题，而不是 bug。**这一点在抽卡游戏里几乎是必须的**，否则无法处理信任危机。

### 27.6 预算与稀有度映射（对应上图）

| 点数 | 稀有度 | 孵化时长 |
|---|---|---|
| 1–5 | 普通 | 8 秒 |
| 6–11 | 稀有 | 30 秒 |
| 12–18 | 史诗 | 2 分钟 |
| 19–28 | 传说 | 10 分钟 |

四种「全同品质」的天然对齐验证了这套数值是自洽的：

```
4 层全白 = 4 点  → 普通  ✓
4 层全蓝 = 8 点  → 稀有  ✓
4 层全金 = 16 点 → 史诗  ✓
4 层全红 = 28 点 → 传说  ✓
```

> ⚠ **这组阈值是模拟 3000 次抽卡后上移过的。** 最初定的是 1–4 / 5–8 / 9–16 / 17–28，但 4 层品质独立时平均点数是 9.84，正好落在「史诗」——实测分布变成普通 2%、史诗 54.5%，稀有度完全失去区分度。上移后变成普通 8.4% / 稀有 61.6% / 史诗 27.8% / 传说 2.2%，且四个对齐点原样保留。

**层数决定「维度数量」，点数决定「稀有度」。** 这两个变量互不替代：抽 3 层全金（12 点）是史诗，抽 4 层全白（4 点）是普通——**前者更强但不完整，后者完整但平庸**。

**顺带解释了一个看似矛盾的现象**：4 层抽卡的「普通」只占 8.4%，是因为**普通不是靠抽出来的，是靠提前定稿拿的**——2 层定稿只有 2–3 点，必然是普通。追求普通的人根本不会抽满 4 层。这是中途定稿机制的必然结果，不是数值缺陷。

### 27.7 定稿规则

| 条件 | 规则 |
|---|---|
| 最低门槛 | 至少选了**载体** + **属性或效果**其中之一（即 ≥ 2 层） |
| 中途定稿 | 随时可定稿，稀有度按当前点数结算 |
| 定稿消耗 | 扣 1 次生成额度 + 材料 |
| 放弃重来 | 不扣额度、不扣材料、不返还已用的定向卡（防「先用再退」） |

**「放弃不返还定向卡」是必须的**：否则玩家会「先押定向卡试一把，不满意就放弃重来」，等于免费反复定向。

### 27.8 SynergyLink —— 协同与冲突

```
{ from: "elem.lightning", to: "attr.fire_rate", type: SYNERGY,
  delta: +0.15, desc: "感电概率 +15%" }
{ from: "attr.pierce", to: "attr.fire_rate", type: CONFLICT,
  delta: -0.20, desc: "单发伤害 −20%" }
```

三条实现约束：

**① 只在「已选词条之间」计算**，不预计算全表。每次选完一层，遍历已选列表两两查一次即可（最多 4 个词条 = 6 对，可忽略）。

**② 必须双向定义或运行时双向查**。A 对 B 有协同，B 对 A 也应有——建议只写一条，运行时双向匹配，避免手填两份导致不一致。

**③ 冲突必须显示在卡面上，不能藏起来。** 只显示增益，玩家会认为系统在推销；显示出「选了它就削弱你现有的属性」，玩家才会思考。

### 27.9 TargetCard —— 定向卡

```
{ id: "target.carrier.dragon",
  target_layer: CARRIER,
  target_affix: "carrier.dragon",
  quality_floor: NONE }
```

| 字段 | 说明 |
|---|---|
| `target_layer` | 作用于哪一层 |
| `target_affix` | 锁定词条 id；`null` = 通用卡（开卡时选） |
| `quality_floor` | 品质下限，首版一律 `NONE`（只保类型不保强度） |

`quality_floor` 字段留空但保留，是为了以后若要加「高级定向卡（保蓝以上）」不用改结构。**首版坚决不用。**

### 28.1 最低门槛的一个 UI 细节（不写死会被骂）

门槛不能只做后端校验，**必须体现在按钮上**，否则玩家会点了才发现不行。

| 当前已选 | 定稿按钮 | 提示文案 |
|---|---|---|
| 只有载体 | 灰显 | 「还需选择 1 项属性或效果」 |
| 载体 + 1 层 | 可用 | 正常 |
| 载体 + 3 层 | 可用，且显示「当前 12 点 · 史诗」 | 正常 |

**顺带确认一件事：2 层定稿是特性，不是缺陷。** 载体（1 点）+ 属性（1 点）= 2 点 → 普通、8 秒孵化。这正好是「快出便宜货」那一档，和 §26.3 的「中途定稿」设计完全一致。玩家用 2 层定稿省时间省材料，用 4 层定稿赌强度——**这个取舍成立的前提就是门槛低**。如果门槛提到 3 层，快档就消失了。

## 29. 450 词条铺满方案

### 29.1 先纠正一个预期：450 条不能靠手写

一个策划手写 450 条词条 + 1800 个品质档位，按每条 10 分钟算是 **75 小时**，而且必然出现命名不一致、数值漂移、ID 拼错。**手写这条路在铺满时不可行。**

正确做法是**「族 × 载体」程序化展开**：

```
族定义（手写，约 50 个）：{ 名称, 单位, 基础值, 适用载体优先级列表, 元素限定? }
        ↓ 展开
450 条词条（脚本生成，ID/数值/文案全部一致）
        ↓ 每族四档
1800 条品质数据
```

于是**手工工作量回到 50 个族**，和之前说的「60 条」几乎一样，但产出是 450 条。**铺满的成本没有想象中高，因为它是乘法而不是加法。**

### 29.2 450 的分配

| 层 | 条目 | 构成 |
|---|---|---|
| 载体 `CARRIER` | **18** | 6 装备（枪/剑/弓/斧/法杖/护甲）+ 5 消耗品（苹果/药水/卷轴/炸弹/盛宴）+ 7 召唤物（龙/兽/精灵/傀儡/幽灵/虫群/晶簇） |
| 元素 `ELEMENT` | **9** | 雷/火/冰/毒/光/暗/岩/风/物理 |
| 属性 `ATTRIBUTE` | **243** | 61 个族 × 载体展开，含 9 元素特化（元素伤害/抗性/亲和/光环） |
| 效果 `EFFECT` | **180** | 30 个族 × 6 载体 |
| **合计** | **450** | |

> 实际数据已生成，见 `orbcraft/core/src/main/resources/data/affixes.*.json`，条目数由校验器强制等于 450。

### 29.3 ⚠ 铺满后冒出来的新约束：同层必须去同族

这是铺满之前不会遇到的问题。池子小的时候（60 条），同一层出现「伤害 +2」和「伤害 +3」的概率很低；**铺满后每个载体有 20 多条候选，同族重复出现几乎是必然。**

玩家看到下面这五张牌，会直接认定系统坏了：

```
[ 伤害 +2 ]  [ 伤害 +3 ]  [ 伤害 +4 ]  [ 暴击 +4% ]  [ 穿透 +1 ]
     白            蓝            金            白            蓝
```

三张卡说的是同一件事，只是数值不同。**这不是选择，是把同一个选项复制了三遍。**

必须加一条硬规则：**同一层内，每张卡必须是不同的 `family`（族），不只是不同的 `id`。**

```
池 = filter(carrier, element)          # §27.4
池 = distinct_by_family(池)             # ← 新增，铺满后必需
池 = exclude_selected_family(池)        # 跨层也不能重复同一个族
```

这条规则使「元素特化」的设计变得很关键：`attr.elem_damage.fire.gun` 和 `attr.damage.gun` 是**两个族**（元素伤害 vs 物理伤害），所以能同层共存——这正是想要的效果，一张是通用伤害、一张是元素伤害，玩家会做真实取舍。

### 29.4 SynergyLink：原计划 200 条，实测去重后 155 条

协同是唯一**不能靠乘法生成**的表，因为「雷 + 射速 = 感电概率 +15%」这句话必须有人真的想过。

最初计划是「60 手工 + 140 派生 = 200」。落地时发现一个必须承认的问题：**手工表和派生矩阵有 45 条撞车**（同一对词条被两边各写了一遍）。去重后真实成立的组合是 **155 条**。

硬凑到 200 只能靠加冗余组合，而冗余协同在游戏里的表现是**同一对词条弹出两行一样的提示**，玩家会认为系统有 bug。所以定案 155：

| 类型 | 数量 | 来源 | 质量 |
|---|---|---|---|
| **CURATED**（手工） | **60** | 逐个设计，覆盖所有主打 combo | 高，是玩法核心 |
| **DERIVED**（派生） | **95** | 从「元素 × 效果」「属性 × 效果」「属性 × 属性」「元素 × 属性」四张矩阵生成 | 中，语义全部成立但不惊艳 |

派生规则举例（模板只要成立，不追求惊喜）：

```
元素 × 状态效果：
  lightning × shock      → 感电概率 +15%
  fire      × ignite     → 燃烧伤害 +20%
  ice       × freeze     → 冻结时长 +1s
  poison    × poison_stack → 中毒层数上限 +2

属性 × 效果：
  暴击率 × 处决          → 处决阈值 +5%
  射速  × 连锁          → 连锁次数 +1
  吸血  × 狂暴          → 狂暴期吸血翻倍
```

**60 条手工的选法**：先写「最直观的那批」（雷+射速、吸血+暴击、冰+击退），因为它们是玩家第一次抽卡就会撞上的组合，手感决定第一印象。剩下的冷门组合交给派生。

> ⚠ **协同数量的正确指标不是条数，是覆盖率。** 一件产物最多 4 个词条 → 6 个词条对。155 条与 200 条对这个命中率的差别不到 5%，但 45 条冗余会让 UI 出现重复行。**要提升体验应该加覆盖率，不是加条数。**

### 29.5 铺满的六条质量护栏

| # | 护栏 | 不做的后果 |
|---|---|---|
| 1 | `id` 全局唯一 | 后写入的静默覆盖前面的，卡池凭空少一堆 |
| 2 | `carrier_allow` 指向的载体必须存在 | 过滤时永远匹配不到，等于该条永不出现 |
| 3 | `excludes` / `SynergyLink` 引用的族必须存在 | 悬空引用，协同永远不触发且不报错 |
| 4 | **每个载体的层 3 / 层 4 候选数 ≥ 8** | 池子抽空，玩家看到 3 张牌 |
| 5 | **每个载体的可用族数 ≥ 8**（去掉同族后仍够 5 张） | 同上，去同族后池子塌陷 |
| 6 | 四档点数必须严格是 1/2/4/7，magnitude 1.0/1.6/2.5/4.0 | 预算校验失效，传说级可以靠堆白卡凑出来 |

第 4、5 两条是铺满后**最容易踩**的，因为「族 × 载体」展开时很容易给热门载体（枪）铺 30 条、冷门载体（护甲）只铺 6 条。校验器会把每个载体的数量打出来。

### 29.6 铺满带来的一个真实副作用（要提前知道）

**池子从 60 条涨到 450 条后，玩家命中「想要的那张」的概率大幅下降，定向卡从「可选」变成「几乎必需」。**

这不是 bug，但它会改变玩家行为：想造龙的人会先攒定向卡，而定向卡要 3 份稀有材料（§26.1）→ 材料来自袭城 → **主循环的转速被抽卡池的深度绑定了。**

两个应对，建议都做：

1. **新手引导必送 1 张定向卡**（之前提过，这里理由更硬了：池子铺满后，不送卡的新人可能一周都抽不到自己想要的）
2. **上线后必须盯一个指标：「用了定向卡的定稿 / 总定稿」**。如果超过 60%，说明纯随机的体验已经不够，要么调高红卡/目标族权重，要么降低定向卡合成价。**这个比例是内容量和随机性之间的平衡指针。**

### 29.8 实测结果：跑完生成器才发现的三件事

数据落地之后，前两版方案里有三个判断是错的。这三个都不是「理论上能想到」的，只有真的生成 450 条才会暴露。

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | **`feast` 的效果池只有 1 条**，玩家抽效果层只有一张牌 | 最初按「族」轮转取数：30 个效果族 × 6 个载体 = 180，正好等于目标数，**第 7 轮一个名额都没有**。凡是追加在族尾的载体（feast 排第 7 位）全被截断 | 改成**按载体轮转**：每轮每个载体各取 1 条，候选少的载体提前耗尽，名额回流给其它载体 |
| 2 | **`armor` 有 15 条属性却只有 7 个族** | 9 条元素抗性（elemResist）属于**同一个族**，去同族后只算 1 个。元素特化族对「池子多样性」的贡献远低于条数 | 补 10 个真正的基础族（regen / resist / summonCrit / summonStatus / summonAggro / stackLimit / triggerRadius / useSpeed / agility / focus），专供冷门载体扩池 |
| 3 | **协同表 45 条撞车** | 手工 60 条和派生矩阵是分开写的，天然会重复 | 生成时按「无向词条对」去重，重复的派生直接跳过 |
| 4 | **`armor` 载体和 `armor` 属性互相误杀** | `family` 不带层级前缀，两者都叫 `armor`，跨层去重时把对方的卡当成「同一族」排除 | `family` 统一加层级前缀（`carrier.armor` / `attr.armor` / `effect.ignite` / `elem.fire`），与 `SynergyLink` 的引用格式完全一致 |
| 5 | **「17–28 点 = 传说」永远达不到**（全红最多 14 点） | 载体层和元素层没有品质档，只有属性/效果带品质，4 层全红只能到 14 点 | 给载体补品质（**做工**：基础属性 +5/8/13/20%），给元素补品质（**元素浓度**：+5/8/13/20%） |

**最终池子分布（每个载体）**：

```
载体        属性/族   效果/族        载体        属性/族   效果/族
gun         15/14     9/9           apple        12/12    10/10
sword       15/12    12/12          potion       12/12    11/11
bow         15/13     8/8           scroll       15/15    11/11
axe          8/8      9/9           bomb         14/14     8/8
staff       15/13    12/12          feast        12/12     8/8
armor       15/10    12/12          dragon       15/13     9/9
beast       11/11     9/9           spirit       15/11    12/12
golem       15/11    10/10          wraith       14/11    11/11
swarm       11/11     9/9           crystal      14/10    10/10
```

最窄池子 **8 条 / 8 个族**，六条护栏全部通过。

**这里有一个比数字更重要的结论：池子深度比总词条数更决定手感。**

抽 5 张牌时，如果某个载体只有 8 个可用族，一次抽卡就消耗掉池子的 62%——**第二次抽这个载体，玩家几乎必然看到重复的组合**。所以「450 条」这个总数是给全服内容量的，**真正影响体验的是「单载体单层的最窄池子」**。这个指标应该写进版本验收，而不是只看总条数。

### 29.9 抽卡模拟：3000 局实测

校验器只能证明「表结构没坏」，证明不了「抽起来对不对」。所以补了一个模拟器，用真实卡表跑 3000 局完整抽卡。

**最终结果（4 层全抽）：**

```
【池子】每层平均可选 8.9 张；凑不满 5 张不同族的层数 0 / 12000；「五张全灰」0 次
【点数】平均 9.9 点（预算 28）；最低 4 / 最高 28
【稀有度】普通 8.4% / 稀有 61.6% / 史诗 27.8% / 传说 2.2%
【红卡】发牌分布 白 37.9% / 蓝 32.1% / 金 22.0% / 红 8.0%（设计值 8%，吻合）
```

**模拟抓到的一个 bug 和一次校准：**

**① 随机数写进 `find` 回调，红卡率从 8% 掉到 2.6%。**

```js
// 错的：find 会对每个元素调用一次回调，于是每比较一次就重新掷一次随机数
card.tiers.find(t => t.tier === rollQuality(rand)) ?? card.tiers[0]

// 对的：先掷一次，再查表
const q = rollQuality(rand);
card.tiers.find(t => t.tier === q) ?? card.tiers[0]
```

后果很隐蔽：`find` 几乎永远匹配不上，全部走 `?? tiers[0]` 兜底成白卡，**表面上看只是「红卡有点少」，实际是整个品质系统失效了**。这类 bug 校验器查不出来，只有模拟分布才能发现。

**② 稀有度阈值与品质分布错配（见 §27.6）**：原阈值让纯随机的平均分正好落在史诗，实测普通 2%、史诗 54.5%。阈值上移到 1–5 / 6–11 / 12–18 / 19–28 后恢复正常。

**传说 2.2% 的解读**：一天 5 次额度，平均约 9 天见一次传说。这个频率我认为是对的——传说应该是「记得住的那一次」，不是每周例行。而且它是纯随机的情况，用定向卡和重抽会显著提高（§25.8 的三档确定性就是干这个的）。

### 31.6 依赖定案与契约落地（v1.9）

**技术基线（锁定，后续所有依赖版本以此为准）：**

| 项 | 定案 | 理由 |
|---|---|---|
| Minecraft | **1.21.11** | 1.21 线最后一版，bug 修完、生态最全 |
| Java | **21** | 避开 Java 25 带来的启动器 / CI / Gradle 全链升级 |
| BetterModel | **2.2.0**（3.x 需 Java 25，不用） | 与 Java 21 对齐 |
| 外观抽象 | `ModelBackend` 接口 | 换成自研时改一个类，不改项目 |

**引入方式的四条硬约束**（写进工程规范）：

1. `modCompileOnly`，**不 `include`** —— 不打包进我们的 jar，玩家不装也能进服
2. 写在 `fabric.mod.json` 的 **`suggests`** 而不是 `depends` —— 否则可选增强会变成硬前置
3. 业务代码禁止 `import kr.toxicity.*` —— 只允许 `fabric` 层的一个适配类接触它
4. 所有模型 id 必须先在 `ModelCatalog` 登记 —— 物理阻断运行时资源包变更

**契约已落地并通过自测**（`orbcraft/core/.../render/`，7 个类）：

| 类 | 作用 |
|---|---|
| `ModelBackend` | 可替换依赖的唯一抽象 |
| `ModelCapability` | FULL / NAMED_VANILLA / NONE，决定要不要提示玩家外观降级 |
| `ModelRequest` | 宿主 UUID + modelId + 缩放 + ARGB 染色 |
| `ModelSpawnResult` | OK / DEGRADED / FAILED + 六种原因，**绝不抛异常** |
| `ModelCatalog` | 预打包清单，运行时资源包变更的硬闸门 |
| `CatalogGuardBackend` | 拦未打包模型 + 吞掉第三方库异常 |
| `ModelBackends` | 按能力降序选择，失败退化到 `NullModelBackend` |

验证结果：`core` 全部 **21 个类** `javac --release 21` 编译通过、零警告；`RenderContractSelfTest` **30 项全通过**，覆盖「依赖缺失 / 模型未打包 / 实现抛异常」三种最坏情况。

### 31.7 ⚠ 需要修正上一轮的一处判断

上一轮我说「BetterModel 让 AI 建模从小时级变成分钟级」，**这话只对了一半**：

- **生成变快了**（`.bbmodel` 是 JSON，AI 可直接产出）✅
- **生效没变快**（新增模型仍会触发客户端资源包重载，全服同时卡 1~2 秒）❌

所以「日常产物 = 预打包骨架 + 染色（毫秒级）」「传说级专属外观 = 异步烘焙（分钟级 ~ 下次上线）」这个分层**必须保留**，不能因为引了库就放宽。变的只是传说级的成本：从「跑一套体素化管线」变成「排进烘焙队列」。

这个修正同时解释了 `ModelCatalog` 为什么是闸门而不是缓存 —— 它挡的不是「查表慢」，而是「随手传一个新模型名导致全服卡顿」这类事故，那种 bug 事后看起来只会像「服务器偶尔卡」。

## 32. 抽卡状态机已落地（v2.0）

`core` 里新增 19 个纯 Java 类，零依赖、不碰 MC，`javac --release 21` 编译通过，**68 项自测全过**。

### 32.1 状态机与三个不能省的设计

```
PICK_BASE ──▶ LAYER_READY ──deal()──▶ LAYER_PICKING ──pick()──▶ 下一层
                  ▲                        │
                  └────── reroll() ────────┘
                                             └─ 四层抽完 ──▶ AWAITING_NAME ──finish()──▶ FINISHED
```

**① `LAYER_READY` 这个阶段不能省。** 它唯一的职责是让定向卡「必须在发牌前使用」这条规则**在结构上成立**。如果把「进入下一层」和「发牌」合成一步，玩家就会先看到牌再决定要不要用卡 —— 那等于免费保底。

**② `AWAITING_NAME` 不等于 `FINISHED`。** 四层抽完只是「抽卡动作结束」，名字还没取、额度还没扣。第一版把两者合成一个状态，结果 `finish()` 直接报「已经定稿了」——自测当场抓到。

**③ 保底只在「提升后仍买得起」时生效。** 强行保底会让玩家拿到一张灰掉的高品质卡，那比没有保底更糟。

### 32.2 三条规则的落地位置

| 规则 | 落在哪 | 为什么在这里 |
|---|---|---|
| 定向卡必须发牌前用 | `LAYER_READY` 阶段校验 | 阶段本身即约束，不靠调用方自觉 |
| 只保类型不保强度 | `TargetCard.guaranteesQuality()` 前置拒绝 | 数据里若出现 `quality_floor`，用的时候直接拒 |
| 目标无效不白耗卡 | `useTargetCard` 里查池子 | 「用掉才发现没用」比「不让用」伤人得多 |
| 每件最多 1 张 | `targetUsedOnce` 在注入成功时置位 | 不是「用了就记」，而是「真注入了才记」 |
| 重抽保留定向 | `activeTarget` 到本层结束才清 | 否则玩家怕浪费卡，不敢重抽，整条重抽链路废掉 |
| 不允许透支重抽 | `reroll(ownedOrbs)` 传入持有量 | session 不掌握玩家余额，强制调用方交代 |

### 32.3 ⚠ 实测暴露的数值结构问题：稀有度通胀

用 450 条真实卡表跑 2000 局「贪心玩家」（每层选能买得起的最高点数，最接近真实行为）：

| 稀有度 | 占比 |
|---|---|
| 普通 | **0.0%** |
| 稀有 | 1.2% |
| 史诗 | 41.8% |
| 传说 | **57.1%** |

平均 18.8 点（预算 28）。**这和之前用「随机选牌」模拟出来的分布（普通 8.4% / 稀有 61.6% / 史诗 27.8% / 传说 2.2%）完全相反。**

原因很直接：**玩家没有理由克制。** 预算 28 是上限，每层都能选到能买得起的最高点数，四层累加自然趋近上限。稀有度于是变成了「玩家愿不愿意少选几张」——而这从来不是设计意图。

再扫一遍不同预算档，规律就非常清楚了（每档 1000 局）：

| 预算 | 平均点 | 普通 | 稀有 | 史诗 | 传说 |
|---|---|---|---|---|---|
| 6 | 6.00 | 0% | **100%** | 0% | 0% |
| 10 | 9.83 | 0% | **100%** | 0% | 0% |
| 14 | 13.68 | 0% | 2.6% | **97.4%** | 0% |
| 20 | 17.61 | 0% | 1.3% | 47.2% | **51.5%** |
| 28 | 18.96 | 0% | 1.4% | 39.1% | **59.5%** |

**结论：预算一旦固定，稀有度就由预算决定，跟抽卡运气无关。** 而「普通」在任何预算下都是 0% —— 因为 4 层最低也有 4 点，贪心更不会选全白。

这也解释了之前那个看似矛盾的现象：**普通不是抽出来的，是提前定稿拿的。** 但玩家没有理由提前定稿（材料够的话，为什么不抽满？），所以「普通」实际上成了不可达档位。

### 32.4 三个候选修法

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 预算由投入决定（推荐）** | 玩家开局选目标档：普通/稀有/史诗/传说 → 预算 6/12/20/28、材料成本 ×1/×2/×4/×8。稀有度即时该档 | 改一条已定规则（稀有度由点数决定 → 由投入决定），但经济闭环立刻成立 |
| B. 点数不再映射稀有度 | 稀有度 = 玩家选的档，点数只算内部强度与孵化时长 | 最简单，但失去「抽得好 = 更稀有」的惊喜 |
| C. 上调稀有度阈值 | 把传说门槛推到 24 点以上 | 治标：预算 28 下贪心仍会撞上限，只是把通胀推后 |

**我推荐 A，理由是它顺手解决了一个更大的问题：材料为什么值钱。**

- 现在：材料只影响「能不能造」，不影响「造多好」→ 材料需求扁平，袭城掉落的价值感弱
- 改后：想要传说 → 材料 ×8 → 必须打袭城、必须挖矿 → **经济闭环自然成立，不需要额外设计**

而且它保留了随机性：同样花 8 倍材料造传说，**词条搭配的好坏仍然是随机的**。玩家赌的不再是「能不能出传说」，而是「这个传说好不好用」——这才是抽卡该有的赌点。

代价是「稀有度」从随机结果变成投入承诺。要保留一点惊喜，可以在 A 之上加一条：**预算档允许小幅跃迁**（例如史诗档抽满 20 点、且四个词条族全不重复，可升为传说）。这条可选，不定也能玩。

### 32.5 这一轮验证到的、可以放心的结论

```
2000 局：池子抽空 0 次 · 「五张全灰」0 次 · 每层都发满 5 张
定向卡：注入成功率 100%（200 次目标全部出现，且品质分布覆盖多档）
重抽：定价 1→2→3 递增、保留已选、保留定向、球不足拒绝且不扣次数
种子：同 seed 逐字节一致，不同 seed 不同
```

**池子深度这件事可以放心了**：450 条铺满之后，没有任何一种「基调 × 载体 × 元素」组合会抽空，也没有出现过「可选不足 2 张」。
